  `app/styles/` 令牌与分层样式、根目录

## 1. 设计立场

Stemmio 的设计只追求两件事：

1. **秒懂**。用户理解成本最低：复杂度低、交互和文字提示一眼即懂、
   全产品一致。用户心智模型必须能压缩到几句话
   （见交互流程第 1 节，目前是五句）。
2. **极简优雅的美学**。简约、优雅、安静的高级质感：中性纸感底色、
   单一强调色、一层阴影、紧凑排印。工作台使用清透白底与深色文字，
   高级感来自克制与一致，不来自装饰。

两者没有机械的优先级：绝大多数时候，最简约优雅的方案恰恰也是最秒懂的。
真正冲突时逐案权衡，在 PR 或 design-qa.md 条目里写清取舍即可；
唯一的常识是——以理解成本为代价换来的装饰，通常两头都输。

## 2. 设计原则

每条原则给出定义、产品中的既有实例和禁止形态。新 UI 决策先对照这八条；
故意偏离时在 PR 或 design-qa.md 条目里说明理由。

### 2.1 秒懂优先

控件自己解释下一步，不依赖说明书。

- 实例：发送主按钮先从“写评论后再发送”进入“发给 AI”，再按交付方式分支：复制模式
  显示“正在复制…”与“复制失败，再试一次”，受管 Qoder 显示“正在启动 Qoder…”、
  “Qoder 正在处理”或“Qoder 会话已中断”。每个状态直接告诉用户现在能做什么。
- 实例：“怎样交给 AI？”只使用一个固定尺寸弹窗；Qoder 的可用、未安装、需要登录和
  暂时无法检查都在同一品牌卡内原地展开，“复制任务”始终留在旁边，不跳 About。
- 实例：画布上"单击选择，双击改字"，与桌面系统惯例一致。
- 禁止：需要悬浮提示才能理解的主要动作；同一动作在不同界面叫不同名字。

### 2.2 单强调色

全产品只有一个强调色家族（靛紫 `--indigo` 系）。对比、选中、焦点、
链接式强调全部落在这一个家族里。

- 实例：AI 审阅工作台的"one-emphasis-color rule"——中性灰控件 + 唯一
  紫色选中态；修改前/后身份只用一个安静中性点和一个紫点，
  红/绿对比面被明确禁止。
- 语义色是事实标注，不是强调：绿（`--green`）只表达"安全/当前有效"
  这类事实，红（`--red`）只用于错误与不可逆动作确认。琥珀面（米黄底
  `#fffaf0`、深棕文字、黄棕描边）是"警告/注意"事实的既有第三语义面，
  在审阅通知、校验决定、处理摘要与项目资源错误中一致使用；它不承载
  动作、不新增色相变体。
- 禁止：引入第二个强调色；用红/绿表达"变化方向"；渐变色新面。

### 2.3 安静优先

界面默认沉默，只在需要用户注意时出声，且声量与事实相称。

- 实例：顶栏不提供保存状态区域；正常写入保持安静，失败进入全局恢复提示。
- 实例：项目状态点保留在标签页和左侧项目上下文中，不在顶栏重复状态文字。
- 实例：Qoder 准备状态只使用短文字和 6px 小圆点；安装、登录或检查失败不铺大面积
  警告色，也不为预期失败追加 Toast。
- 实例：更新提示是贴在图标下缘的小号 `New!` 标签，下载过程无百分比、
  无动效、无横幅。
- 实例：Review 总览只保留精确字符证据与页边导航提示；聚焦时允许只有局部遮罩孔而没有边框。
  每侧最多一个局部边框，文字变化永不为“让变化更明显”而补画段落框，样式变化也只有在视觉变化
  已由当前局部目标自己的纯样式证据确认时才画框。跨越一屏或接近整页的大容器继续可定位、可遮罩，
  但不画巨型边框，也不裁成假的视口框。评论气泡按内容自适应宽度并允许指针进入阅读；点击或
  `Escape` 关闭临时评论层后，恢复原变化聚焦而不留下常驻虚化。
- 禁止：常驻徽章、无事实变化的动效、把普通状态渲染成警告。

### 2.4 诚实文案

状态文字必须反映底层事实，绝不提前或含混。

- 实例：复制模式显示“已复制至剪贴板”，受管 Qoder 模式则显示真实的启动、读取、写入
  或最终化阶段；二者都不能用笼统的“已完成”提前替代 Candidate 校验事实。
- 实例：AI 阶段完成不得从输出文件存在、耗时或泛化错误推断；
  "已安全保存"要求编辑 revision 已持久化且当前画布回报同一源 Hash。
- 禁止：乐观式完成态；把内部实现词（事务目录、commit marker）
  暴露给用户。

全局 Toast 使用窗口顶部居中的轻盈浅紫胶囊：细边框、紧凑文字、柔和阴影；长文案可自然换行，动作与关闭按钮保留键盘焦点样式。普通信息短暂出现，阻止继续编辑的故障保持可见并提供恢复动作；可编辑的静态降级不弹常驻黄色提示。画布内定位型反馈仍留在目标上下文。

### 2.5 同类同形

同一类控件在全产品只有一种处理方式。新功能复用既有 treatment，
不发明第二套。

- 实例：Qoder 交接页脚的新动作复用既有按钮类，"instead of adding a
  second button design"；审阅工作台两组分段控件共享同一外观。
- 实例：交付侧栏和 Settings 复用同一个 Qoder 状态卡组件、状态文案与操作层级，不能各自
  推断“可使用”或“未安装”。
- 实例：图标一律来自既有 Phosphor 包。
- 实例：悬浮提示统一走 `[data-tooltip]` 机制（悬浮与键盘聚焦皆可见，
  默认显示在控件上方；`data-tooltip-side="below"` 用于画布工具条等
  上方空间受限的场景），不再为控件新增原生 `title` 提示。
- 实例：提示的生命周期只绑定指针悬浮与 `:focus-visible`。不绑定
  `:focus` / `:focus-within`：鼠标点击会让按钮保留焦点，那两个状态会把
  气泡钉在屏幕上。控件自己展开的面（`aria-expanded="true"`）在场时，
  提示让位：那个面就是解释，气泡不得叠在它上面。
- 禁止：一次性的按钮样式；emoji、手绘 SVG、CSS 画图或占位图充当图标。

模式切换器的几何、默认与 hover／pressed／disabled／focus 状态统一由
`app/styles/top-toolbar.css` 定义；共享 chrome token 保留原所有者，基础层不再
叠加此组件的替代样式。编辑／预览／审阅共用无外框的图标文字入口，当前模式以
深色文字和细靛紫下划线标识；项目与设置导航使用中性灰选中底面。
编辑／预览不显示不可用的 Review 子控件，Review 门户槽仍常驻。
空变化在画布原位显示一条安静说明；审阅不提供全部/文字/元素类型筛选。
窄窗口下会话面板可覆盖审阅画布，但必须完整留在可视区并保持关闭控件可命中；不得继承宽屏 Grid 列而落到视口外。

### 2.6 几何稳定

界面元素不因悬浮、聚焦或内容回流而跳动。

- 实例：评论卡片的 30px 动作行在默认态就预留高度，hover 只改透明度，
  ResizeObserver 不会因指针进入而移动邻卡。
- 实例：发送弹窗为异常展开预留固定高度；检查中、安装引导与登录引导切换时外框不跳动。
- 实例：悬浮提示与更新标签绝对定位，不参与布局计算；原生文字编辑期间
  评论目标几何冻结，回流不会让邻卡跳动。
- 禁止：hover 改变尺寸、出现二级布局抖动、遮挡相邻控件或越过分隔线。

### 2.7 渐进披露

次要信息默认折叠，动作在需要时才显现；状态与决定分离。

- 实例：其他标签页评论折叠在头部内，展开也留在头部里；
  评论卡片工具在 hover/键盘聚焦时才显现。
- 实例：交接流程卡片只承载状态，所有决定（重试、打开、稍后）
  固定在页脚——决定的位置永远可预期。
- 禁止：把所有动作平铺在默认态；在状态卡片里藏决定按钮。

### 2.8 无障碍与从容降级是底线

不是加分项，是每次 design QA 的必查面。

- 实例：分段控件支持方向键与 Home/End；对话框捕获并归还焦点；
  `aria-pressed`/`aria-current`/live region 与视觉状态同步；
  reduced motion 移除过渡；IME 组合期间 Enter 永不提交。
- 禁止：仅鼠标可达的路径；焦点丢失；组合中的输入被当作提交。

## 3. 视觉基础

数值的唯一真相是 Workbench 级联入口 `app/globals.css` 导入的 `:root`
令牌（`app/styles/tokens-and-base.css`）；外壳语义别名由
`app/styles/workbench-chrome.css` 的 `:root` 定义，供工作台与 Portal 共用。本表只定义语义与
使用规则，改值不需要改本文；新增或重定义令牌才需要。

| 令牌 | 语义 | 使用规则 |
| --- | --- | --- |
| `--shell` / `--panel` / `--paper` | 白色应用壳与纸面、近白辅助面 | 编辑、预览、审阅、设置与右栏使用同一底色逻辑，不用大面积灰紫区分层级 |
| `--ink` / `--muted` / `--faint` | 文字三级：正文 → 次要 → 微弱 | 文字层级靠灰度，不靠字号膨胀 |
| `--line` / `--line-soft` | 分隔线两级 | 边框一律 1px、单层 |
| `--indigo` / `--indigo-deep` / `--indigo-soft` | 唯一强调色家族 | 选中、焦点、强调、评论标记 |
| `--green` / `--red` | 语义事实色 | 见 2.2；不用于对比方向 |
| `--shadow` | 全产品唯一投影 | 一层阴影；禁止叠加第二层光环 |
| `--ui` | 系统字体栈 | 界面文字唯一字体来源 |

排印与密度：

- 界面控件使用 9–15px 的紧凑层级；模式名、标签保持单行，
  不截断核心词。
- 展示型宋体（Songti）只用于欢迎页 hero 的社论式表达，
  不进入工作界面。
- 卡片间最小可见间距 16px；大表面圆角 15–16px；
  图标 12–20px，与既有工作台一致。

材质与虚化：

- 浮在内容之上的表面（画布浮动工具、通知、抽屉）使用
  同一玻璃配方：半透明白 + `blur(16–20px) saturate(160–180%)` +
  顶部 1px 内高光；不透明度按可读性取 76–92%，不做 95% 以上的
  “假虚化”。
- 模态遮罩统一暖雾：`rgb(34 32 27 / 36%)` + `blur(16px) saturate(140%)`，
  模糊随过渡从 0 渐入；灯箱等暗房场景可保留深色。
- 固定外壳不铺噪点、渐变或有色阴影；白色底面、深色文字与轻分隔线建立层级。
  左侧导航使用近白底色；评论卡片保留细边框、锚点连接和轻微中性投影，
  聚焦用局部强调线与键盘轮廓表达。AI 输入框与弹出菜单沿用轻微中性投影。
- 网格布局中不覆盖任何内容的固定区域（顶栏、固定侧栏）不做毛玻璃——
  虚化只用于真正有内容透过的表面。

## 4. 文案

- 中文短句，动词开头，直接说结果或下一步。
- 状态词分两档：安静标签（"未保存"）与真实警示（保存失败）；
  不升档渲染。
- 不可逆动作使用原位确认（"删除这条评论？"），不弹全局对话框。
- 通知与启动文案的完整目录见
  [NOTIFICATION_MESSAGE_CATALOG.md](NOTIFICATION_MESSAGE_CATALOG.md)。

## 5. UI 修改标准流程（Design QA）

适用于任何用户可见的视觉或交互变化。轻微修改（一处文案、一个既有令牌
的应用）不必走截图流程，在 PR 里对照第 2 节说一句即可。

1. **定视觉真相**：确定本次的 source visual truth（用户截图、Figma 或
   既有界面），并显式记录哪些细节已被后续产品决定取代（supersede），
   避免对着过期稿逐像素较真。
2. **归一化对比**：实现截图与真相图统一视口与像素密度后再比较；
   同时做全景对比（层级关系）和聚焦对比（控件细节）。
3. **七个保真面逐一核对**：字体排印 / 间距节奏 / 颜色令牌 / 资产保真
   （Phosphor-only）/ 文案 / 图标与控件状态 / 无障碍与降级。
4. **发现分级**：P0（阻断）、P1（必须修）、P2（记录后续，不扩大已通过任务的范围）；
   P3 记录为后续打磨，不阻断验收。
5. **修复后复拍**，在条目中保留对比历史——问题、修法、复核证据。
6. **追加条目到根目录 `design-qa.md`**，以实际 `final result: passed / partial / blocked` 收尾，列明未验证项。
   截图证据放 `output/design-qa/`；用户提供的真相图不入库。

用户提供的真实截图始终优先于生成稿；真相图中被用户后续标注否决的
部分按否决执行（`design-qa.md` 已有多个先例）。

## 7. 何时更新本文

- 新增/重定义令牌、引入新的组件 treatment、或推翻任何一条原则时，
  在同一 PR 更新本文。
- `design-qa.md` 是执行日志，只追加；本文是合同，保持精炼。
  日志中反复出现的新共识应提炼进本文，而不是留在日志里靠考古发现。
