# Stemmio 版本与项目文件产品需求

- 文档版本：PRD v2.1
- 最近更新：2026-09-27（Asia/Shanghai，UTC+8）
- 状态：已确认的当前产品合同；交付状态以 CHANGELOG、测试和发布记录为准
- 适用范围：桌面 HTML 项目、当前稿、不可变历史、本地保存版本、AI 采纳、HTML 导出、存量项目迁移与恢复
- 关联文档：[导入确认](IMPORT_CONFIRMATION_PRD.md)、[MVP 产品需求](MVP_PRD.md)、[交互流程](INTERACTION_FLOW.md)、[架构合同](ARCHITECTURE_CONTRACT.md)、[状态所有权](STATE_OWNERSHIP.md)、[安全模型](SECURITY_MODEL.md)

本文是完整的现行产品合同。每个 Version 分配一个可编辑工作文件、激活旧 Version 的工作文件、按阶段保留两套历史入口等规则已退役。具体持久化格式与事务实现由关联技术合同定义，不能从旧文件名或旧分期文字推导另一套产品行为。

## 1. 产品结论

一个项目只有一份可编辑的**当前稿**。普通编辑持续保存到它；V1、V2、V3……是项目内不可变的历史快照。用户可以随时查看任何历史版本，包括最新版本；查看历史不改变当前稿。

- 首次导入建立当前稿和初始历史 V1。
- 自动保存和 `⌘S` 只保存当前稿，不增加版本号。
- “保存到历史版本”把当前稿明确保存成下一份历史快照，随后继续编辑同一当前稿。
- AI 输出先成为待审阅 Candidate；明确采纳才创建下一版本并更新同一当前稿。
- 从历史继续工作先明确创建下一版本，再更新同一当前稿，不把旧快照变成可编辑文件。
- “导出当前 HTML…”先询问导出选项，默认勾选“同时保存到历史版本”；用户可取消勾选，只导出 HTML。

项目、当前稿和历史身份独立。当前稿即使与最新历史字节相同，也始终有自己的入口，不能把最新历史行兼作编辑入口。

## 2. 对象与身份

| 对象 | 作用 | 可变性 |
|---|---|---|
| 外部原 HTML | 用户首次选择的来源文件 | Stemmio 不回写；默认保留 |
| Project | 容纳当前稿、历史、规则、评论和 AI 任务 | `projectId` / `documentId` 稳定 |
| 当前稿 | 项目唯一可编辑 HTML 及其当前评论、附件和保存状态 | 本地编辑、明确采纳或恢复会更新 |
| Working Copy | 当前稿的内部身份与持久化状态 | 一个项目只有一个活动受管 `workingCopyId` |
| Version | 已正式建立的 HTML 历史快照 | 内容、来源与生成时间不可变 |
| Candidate | AI 已返回、尚待决定的结果 | 通过校验后只读审阅；尚不是正式 Version |
| 保留的稿件 | 被替换前或迁移时保留的 HTML、评论草稿及附件证据 | 不能静默成为当前稿；明确恢复后创建新 Version |
| Request / Attempt | 本轮冻结输入、AI 执行和完成证据 | 冻结输入不可变，不由可见文件副本反向重建 |

`projectId`、`documentId`、`workingCopyId`、`versionId`、路径和内容 Hash 各有职责。Hash 只证明字节关系，不能决定项目归属、授予写入权限或把所选历史跳到当前稿。`viewingVersionId` 只描述正在查看的历史；不能从当前稿的基础版本或 ID 相等推断历史选中状态。

## 3. 当前范围

本次范围是让用户在应用内明确区分当前稿与历史、主动保存本地版本、导出正确 HTML，以及安全处理旧工作稿与 Finder 变化。

下列能力暂不提供，也不作为本次验收前提：项目归档、删除管理菜单、项目搜索、克隆、完整项目导入/导出、评论审阅包、备份包、资源打包、可见附件文件管理、多文件网站管理、任意移动项目根后的重新关联。现有评论附件持久化和冻结 Request 的保护不因这些功能延期而退化。

现有“新建项目”仍通过选取并确认导入 HTML 建立项目，不增加空白网页编辑器。旧的受管 HTML basename 重命名能力不能称作“项目重命名”；本次不新增项目管理菜单或顶栏改名入口。

## 4. 版本号、谱系与文件名

### 4.1 连续编号

正式历史使用一套连续整数 `V1`、`V2`、`V3`……；内部 ID 如 `ver_0003`。本地保存、历史创建、恢复和 AI 采纳共享同一序列。失败、取消、AI no-change 和未采纳 Candidate 不消耗正式版本号。

每份新版本分别记录：

- `basedOnVersionId`：内容基于哪个版本。
- `previousVersionId`：创建前项目的最新正式版本。
- 精确内容 Hash、生成时间与来源类型；AI 版本额外关联 Request / Candidate。

例如项目最新 V6，用户从 V2 创建新稿，得到 V7：V7 基于 V2，前一正式版本为 V6。随后在当前稿上采纳 AI 结果得到 V8，其基础与前序为 V7。不能把 V2 的不可变快照改成 V7 的内容。

### 4.2 当前稿命名

新导入 `产品首页.html` 时，可见当前稿为项目内 `产品首页.html`；`.htm` 后缀同样保留。不再为每次建版生成 `产品首页-V2.html`、`产品首页-V3.html`。

新版本、历史创建、恢复和 AI 采纳均保持当前 `workingCopyId` 与当前文件路径稳定。只有明确且已验证的文件改名或受支持的根目录改名才能改变路径。文件名不是版本身份。

存量项目迁移保留用户实际活动工作文件的路径和名称；已有 `产品首页-V2.html` 不因升级被强制改名。它迁移后是唯一当前稿，名称中的 `V2` 不限制未来版本号，也不代表它仍是一份不可变 V2。

## 5. 项目目录与文件权限

新项目示意：

```text
<配置的项目目录>/<项目名>/
├── 产品首页.html                 # 唯一当前稿
├── PROJECT.md                    # 项目长期规则
├── AI任务/                       # 既有可删除、可重建的派生展示
└── .stemmio/                    # 版本快照、当前状态、Request 和恢复证据
```

Registry 决定项目目录成员与允许管理的根；项目内稳定身份及 manifest 证明具体成员。Recent 只提供最近打开等展示事实，不能授权文件、创建成员或移除项目。项目显示名来自已登记项目文件夹名；HTML 改名不等于项目文件夹改名。

用户自行放入项目目录的其他文件不自动受管，不被版本化、冻结、移动或删除。产品不扫描整个磁盘，不因同名或相同 Hash 认领文件。重复身份隔离对应项目，不阻止其他项目浏览。

项目内 `device / inode / birthtime` 只可作为本次文件观察，不是跨重启的身份凭证。恢复改名或返回路径必须同时具备唯一稳定身份、登记成员关系、安全路径和可验证内容证据；隐藏绑定不能扩大到登记根外的写入权限。

## 6. 首次导入与再次打开

打开流程以 [导入确认 PRD](IMPORT_CONFIRMATION_PRD.md) 为准：

1. 有效受管项目直接进入当前稿；明确历史导航进入指定快照。
2. 已关联的外部原稿显示“已经导入”，主操作为“打开之前的项目”，回到该项目当前稿。
3. 真正新的外部 HTML 先确认，再原子建立项目、V1、唯一当前稿和外部源关联。

V1 保存首次导入时所选文件的原始字节。应用不向外部原稿或 V1 回写 Stable ID；来源文件已有的字节也不被清洗。当前稿在导入/打开时物化持久 Stable ID，因此可能与原始 V1 字节不同，这不被单独当作用户本地修改。

默认保留原稿。只有用户明确勾选且项目、关联和新画布均已确认，才将该原稿移至废纸篓。取消和导入失败不改变当前项目、原稿或历史。导入不复制同目录的图片、CSS、脚本等资源，也不建立外部原稿的双向同步。

再次打开始终回到当前稿；即使最新历史内容不同，也不自动替换。有效旧 v4 项目按 §12 迁移；v4 以前的记录不作为兼容状态读取，用户选择其中 HTML 时仍走外部文件确认。

## 7. 普通编辑与保存

文字、样式和结构编辑持续写入同一当前 HTML。评论、附件和长期规则由各自既有保存工作流持久化，不能塞入 HTML 或用 HTML 保存成功代替它们的保存回执。

- 自动保存和 `⌘S` 不创建正式版本、不清空评论、不改变当前稿身份。
- Undo/Redo 属于当前打开文档会话，不能替代版本历史，也不跨项目、关闭或重启恢复旧操作栈。
- 已建立的全部 Version 永远不被后续本地编辑改写，包括最新 Version。
- 普通成功保存保持安静；失败保留完整当前内容及恢复证据，并阻止使用未经确认的源文件进行 AI 冻结或覆盖写入。
- 源码是保存、版本和导出的事实源；Runtime DOM 和截图不是可回写 HTML。

## 8. 保存到历史版本

当前稿的“更多”菜单提供独立的“保存到历史版本”。用户无需导出或调用 AI，也能留下本地历史节点。

流程：先收口当前原生编辑并保存最新完整 HTML，验证项目身份、源 Hash 和并发状态，再以一个稳定操作身份保存不可变快照并更新当前稿基础版本。当前 HTML、路径、`workingCopyId`、评论与附件继续保留；长期规则不回滚、不随版本复制。

如果当前内容与当前已登记的快照基线一致，返回“当前内容已保存在历史版本中”，不增加编号。初始化 Stable ID 本身不触发额外本地版本；仅评论或附件变化也不单独建立 HTML 版本。

正常结果就近显示“已保存 Vn”，可关闭，不增设常驻状态条。未知提交结果先查询同一操作；已创建但刷新失败只刷新/打开既有结果，不能重复分配下一编号。Request 或待决定 Candidate 活跃、项目身份或当前 Hash 不确定时，不允许另行建版。

## 9. HTML 导出

### 9.1 导出的内容

- 当前稿：“导出当前 HTML…”复制收口后完整、精确的当前 HTML，包括已有 Stable ID。
- 历史：“导出此版本…”复制正在查看的已校验不可变快照，最新历史也遵守此规则。
- 不序列化 Runtime，不清洗或改写作者源码，不嵌入评论、附件、项目规则或内部记录。
- 导出的普通 HTML 不是评论审阅包或项目备份。另一人导入后不能凭 HTML 自动获得原项目的评论、历史或管理身份。

### 9.2 可选保存版本

点击当前稿导出项先打开对话框；每次默认勾选“同时保存到历史版本”，说明它保留此刻内容供以后查看，用户继续编辑同一当前稿。用户确认“选择保存位置…”后才打开系统保存窗口。版本暂不可保存时就近说明原因并允许单独导出；历史直接导出，不提供此选项。更多菜单本身没有复选项。

未勾选时，无论导出多少次都不新增 Version。勾选时，先成功导出本次冻结的精确 HTML，再用同一份内容和 Hash 请求保存新版本；不能在导出期间混入更晚编辑。

- 保存对话框取消：不导出、不创建 Version。
- 文件写入失败或目的地不允许：不创建 Version，保留当前稿。
- 导出成功且内容无变化：文件照常导出，不重复建版。
- 导出成功但建版失败/结果未知：清楚保留“文件已导出”事实，提供查询或重试保存版本；不要求重新导出，也不伪装整个操作失败。

导出不改变当前打开项目、路径、Recent、外部源关联或评论草稿；只有确认勾选项并成功建版时改变正式历史。

### 9.3 目的地与结果

首次默认目录为 Downloads；之后使用最近一次成功的外部导出目录。取消或失败不更新该偏好。项目目录、其他项目及隐藏记录、路径/硬链接别名均不能作为覆盖目的地；不能用户选中受保护路径后偷偷写到别处。正常外部文件覆盖仍由系统保存流程确认。

成功结果可“显示文件”。该定位权限只针对本次已验证导出结果，不授予任意文件读写权限。

## 10. AI Candidate 与采纳

发送前先保存并冻结当前完整 HTML、评论、附件、长期规则及其 Hash。冻结输入必须包含 V3 之后已完成的本地编辑；不能只把 V3 快照当作 AI 输入。

AI 只能写入既定 Attempt 输出；输出通过身份、路径、Hash、完整 HTML 和现有安全校验后，成为待审阅 Candidate。可见 `AI任务/` 仍是派生展示，删除或篡改它不会修改冻结 Request、Candidate 或正式历史。

明确采纳时：

1. 重新验证当前稿、Request、Candidate 与用户审阅的精确字节。
2. 在替换当前稿之前保留原当前 HTML、评论草稿和附件恢复证据。
3. 创建下一份不可变 Version，并以同一份已校验 Candidate 内容更新同一当前稿。
4. 更新当前稿基础版本与项目最新正式版本，保持项目、文档、Working Copy 身份和路径。
5. 完成已冻结评论的既有归档后才建立本轮新草稿；提交和打开状态分别真实展示。

例如 V3 后用户又做本地编辑，再采纳 AI 得到 V4：V3 仍是原快照；V4 是已采纳结果；AI 前本地内容可从保留稿件找回。不能为了让 V3 看起来包含后续编辑而重写 V3，也不偷偷多建一个版本消耗 V4 编号。

失败、取消、拒绝或 no-change 不新增 Version。发现外部并发修改时保留双方内容并进入冲突，不以“采纳”绕过源 Hash 或登记根校验。一个项目同一时间只有一个活动 Request 或待决定 Candidate，其他项目可继续工作。

### 10.2 候选身份

每个 Candidate 必须绑定所属项目、文档、Request/Attempt、来源 Working Copy、拟建 Version、输入与输出 Hash。Candidate 文件、展示副本和运行时状态都以该身份和完整 HTML 校验为准；缺少任一字段、路径越界、Hash 不符或运行时封印被篡改时，Candidate 只能进入错误/待处理状态，不能创建 Version。

### 10.3 用户审阅

Candidate 通过完整 HTML、结构身份和来源 Hash 校验后才进入审阅。审阅页只读展示当前稿与候选结果，允许用户查看变化、返回或明确采纳；审阅期间不覆盖当前稿、不把 Runtime 内容当作源码，也不因“有变化”自动取得写入权限。空差异仍可审阅，但不改变版本事实。

### 10.4 采纳候选

采纳必须携带与 Candidate 精确匹配的 `candidateId` 和 `decisionOperationId`，再次核对当前稿、Request、Attempt、来源 Hash 及候选输出。通过后先保留被替换当前稿，再创建下一份不可变 Version，并更新同一当前稿；提交回执丢失只查询或重放同一操作，不重复编号。身份、Hash、路径或并发状态不确定时拒绝采纳并保留原内容。

## 11. 历史查看与创建

### 11.1 左侧项目结构

每个展开项目依次显示：

```text
项目名
  长期规则
  当前稿
  历史版本 ▸
```

历史默认折叠，展开后按 V1、V2、V3……升序显示简短标签和生成时间；来源信息放在需要时查看的详情/提示中，不逐行重复长文件名、当前标记或分支连线。当前稿始终可发现，即使其字节恰好与最新历史一致。

项目展开与历史展开分别保持状态，不切换项目。多个项目可同时展开。当前稿、长期规则和历史都是项目作用域的独立标签页，以“项目名 · 当前稿 / 长期规则 / 历史 Vn”命名；每个项目最多各有一个，关闭后可由左侧栏重新打开。重复点击同项目的另一 Vn 复用历史标签并切换所见快照，不能按每个版本无限增加标签。跨项目点击规则或历史只在目标项目和目标页面就绪后提交活动标签，不能先显示目标当前稿。规则页、当前稿和历史各自只选中真实正在查看的对象；不能用当前 `workingCopyId` 或基础版本相等替代历史选中状态。保留键盘激活、焦点与无障碍名称。

### 11.2 所有历史都只读

点击任何 Vn 都读取该 ID 对应的不可变快照，校验 Hash 后进入独立历史标签，包含最新 Vn。历史页直接处于“预览”模式；“编辑”保留在模式栏但禁用并说明继续编辑入口，不增加“只读”模式。历史查看不覆盖或切换当前工作稿、不消耗评论、不新增 Version。路径缺失或 Hash 不符时保留原视图并显示错误，不回退显示另一份 HTML。

历史页不显示额外滑出的“创建新版本并编辑 / 回到当前稿”横条。已打开的当前稿标签或左侧栏当前稿入口结束历史展示并核对当前源状态。当前稿缺失时保持恢复状态，不能冒用最新快照。

### 11.3 从历史继续工作

在历史页点击“更多 → 基于此版本创建新版本…”，先确认“基于 Vn 创建新版本”。取消保持历史和当前稿不变；确认后创建项目的下一个版本，保护被替换前稿件，并更新同一当前稿。所选旧快照及其他历史保持原样。

该动作验证当前项目、所选 Version、快照 Hash、当前稿 Hash、Request/Candidate 锁和稳定操作身份。创建回执丢失只查询同一操作；已创建而打开失败提供“打开已创建版本”，只重试打开。更晚操作已经接替时，旧回执保留创建事实但不能夺回当前稿。

## 12. 存量项目迁移与保留稿件

### 12.1 迁移一个有效旧 v4 项目

迁移必须保留**实际活动** Working Copy，而不是选择最大版本号。例如最新 V6、用户实际在旧 V2 工作稿上编辑时，V2 的当前 HTML、评论、附件、路径、名称和 `workingCopyId` 都成为唯一当前稿；不能自动载入 V6。

其他旧工作稿先按稳定身份保留其 HTML、评论草稿、附件引用与已验证文件证据，再退役多工作文件模型。迁移不改写任何 Version、不新增版本、不把旧工作稿当成已保存历史。不能按文件名、mtime 或相同 Hash 决定哪份是当前稿；无法证明实际活动身份或保留内容完整性时失败关闭，保留原数据。

中断重试应回到同一迁移结果，不丢弃尚未安全保留的旧文件；迁移完成后只有一份受管可编辑当前稿。未知用户文件不参与清理。

### 12.2 找回此前的稿件

常规菜单不再提供“找回此前的稿件”，也不挂载保留稿选择对话框。已有保留数据不删除；保护被替换稿、事务恢复以及 Repository/VersionWorkflow 的身份、Hash、路径和幂等校验保持有效。底层恢复能力不构成重新增加常规入口的依据。只有后续明确产品决定才可重新引入该入口。该变化见 [ADR 0078](decisions/0078-current-draft-file-actions.md)。

## 13. Finder 与项目缺席

### 13.1 改名与返回

配置项目目录内、身份唯一的项目文件夹同父目录改名可更新 Registry 位置和项目显示名；当前 HTML 改名只更新它的路径，不创建 Project 或 Version。文件标识变化不能单独导致不可用，内容相同也不能单独授权绑定。

当前 HTML 移出受管根后，外部位置不受管。原路径或唯一可证明的根内返回文件经重新校验后恢复；外部变化与应用内修改并存时保留双方并要求解决冲突。缺失成员有经过验证的隐藏绑定时，可以使用既有明确恢复动作进行不覆盖恢复；不能从历史快照静默重建用户当前稿。

### 13.2 缺席与不可用

只有成功扫描配置项目根、确认某个**非活动**项目目录不存在，才把该项目从普通列表隐藏。保留 Registry 和恢复证据，不把隐藏视为删除数据；目录返回并重新验证后可再次显示。

扫描失败、权限错误、目录暂时不可读、重复项目 ID 或记录损坏均为“不可用”，不能当作已删除而静默隐藏。错误隔离在对应项目，其他项目仍可浏览。

活动项目根消失时，保留当前内存内容、已确认恢复证据和导出出口，停止向旧路径写入。普通保存、评论、规则、导入重试、建版和 AI 提交都不能重建已消失项目根。目录返回后先重新验证，不能仅因旧路径再次存在就恢复写入。

### 13.3 文件夹动作

当前稿 Finder/默认浏览器动作作用于实际当前工作文件。历史页保留“在 Finder 中显示工作文件”和“在浏览器中打开工作文件”但禁用，并说明历史没有独立工作文件；不能用当前稿响应所见历史的文件动作。“导出此版本…”仍以所选并已校验的历史快照为对象。隐藏历史文件不作为可编辑用户文件发布。项目根入口和既有 `AI任务/` 入口仍只打开经过验证的目标。

## 14. 事务、并发与恢复底线

不可变版本创建、当前稿替换、评论恢复与路径更新必须有稳定操作身份和可查询结果。每次写入前重新验证登记根、成员身份、预期 Hash 与并发状态；任一未知不能覆盖另一份文件或给出虚假成功。

替换前字节必须先有已验证恢复证据。暂存、发布或清理期间外部持有旧文件继续写入时，要保留外部字节并报告冲突，不能删除唯一副本。提交后打开/画布失败不撤销已确认版本事实，也不能重复建版。

源码提交与画布展示是不同事实。只有对应 Session/Hash 的画布确认后才能说“已打开”；旧 Runtime、同 Hash 的另一路径、过期操作或缓存都不能取得新写入权限。Project、Document、Version、Draft 和 Comment 的发布由既有 owner 统一完成，不另建平行全局状态。

### 14.3 候选和采纳失败

Candidate 校验、审阅、采纳或恢复任一步骤失败、取消、超时或结果未知，都不得消耗正式版本号、覆盖当前稿或清理唯一恢复证据。治理边界只允许查询同一操作、保留可核对的失败事实并等待用户处理；不能通过重试新操作、降级到旧路径或绕过身份/Hash 检查来取得成功。

## 15. 验收标准

1. 新导入只有一个 `base.html` 当前稿和不可变 V1；外部原稿保持原字节，取消导入不产生记录。
2. 连续本地编辑、自动保存、`⌘S`、评论和附件变化不自动增加 Version。
3. 独立“保存到历史版本”保存本地 HTML，保持当前路径/Working Copy 和评论附件；重复无变化不增加编号。
4. V1 与最新历史均在独立历史标签中以预览模式打开不可变快照；编辑禁用，当前稿与最新历史相同也有独立入口和正确选中态。
5. 项目结构为规则、当前稿、默认折叠历史；三类页面按项目去重为“项目名 · 页面类型”标签，跨项目打开目标页面不闪现当前稿，历史升序简洁展示，展开不导航，键盘可操作。
6. 导出精确当前 HTML，确认时默认保存对应历史快照，取消勾选则不建版；历史导出精确所见快照；两者均不携带评论包。
7. 导出勾选每次打开导出对话框为开；勾选成功仅对该次冻结内容建版；无变化、取消和导出失败不增号。
8. 导出成功但建版失败保留导出成功事实，查询/重试不再次导出或重复建版；项目内目标和别名不能被导出覆盖。
9. V3 加本地编辑后采纳 AI 得到 V4，V3 不变；AI 输入及保留稿件包含 AI 前编辑与评论。
10. 从 V2 明确创建 V7 后，当前身份/路径稳定，V2/V6 不变；取消不创建，丢失回执/打开失败/重启不重复分配。
11. 更多菜单不显示找回稿件入口和独立导出复选项；底层保留数据与失败恢复测试继续证明原数据不会被删除或覆盖。
12. 旧项目最新 V6、活动旧 V2 时迁移保留 V2 的实际内容、评论、名称、路径与 Working Copy；其他旧稿可找回，不自动切到 V6。
13. 非活动项目明确缺席才隐藏；权限/扫描失败/重复身份保留不可用事实；活动项目缺失时内容可保护/导出，任何后台路径不得重建项目根。
14. 目录/文件返回、外部改名、冲突与事务中断均按唯一身份及内容证据恢复，不按文件名或 Hash 猜测。
15. Node 事务/身份测试与真实 Electron 导航、编辑、导出和恢复测试共同验证；仅修改文档或通过源码检查不能宣称产品已交付。

## 16. 文档与实现边界

本 PRD 统一产品语义；[IMPORT_CONFIRMATION_PRD](IMPORT_CONFIRMATION_PRD.md) 细化外部源归属、确认、删除原稿和打开队列；[INTERACTION_FLOW](INTERACTION_FLOW.md) 细化可观察交互；[MVP_PRD](MVP_PRD.md) 给出产品总范围。技术 owner 文档、Schema、Bridge/IPC、测试和变更记录必须与同一产品语义一致，不能保留“一个 Version 一个 Working Copy”的现行例外。
