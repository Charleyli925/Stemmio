# 源页：提示精简与启动行为

当前所有提醒出口、统计、逐项文案、用户触发场景和小白案例见
[`NOTIFICATION_MESSAGE_CATALOG.md`](./NOTIFICATION_MESSAGE_CATALOG.md)。

## Toast

通用 `setToast` 已退休。产品边界是：

- 不可逆变化 → Confirmation
- 持续内容风险 → `WorkspaceSafetyState`（现有工作区横幅 / 顶栏状态）
- 外部不可见重大风险 → 极少数封闭 `GlobalInterruption`
- 其他所有情况 → 自动处理、保持当前状态或内部日志

业务代码不得自由填写横幅文案。允许的中断只能 `setInterruption({ kind, …facts })`，
标题、语气和按钮来自 `globalInterruptionPresentation()`。

- 全局中断与画布内短提示统一使用 `NoticeBar`：同一套语义色、图标、玻璃材质、关闭按钮、操作按钮和键盘焦点样式。编辑受阻类提示（C02 家族）已全部静默移除。动态内容降级由 `EditRuntimeStaticFallbackNotice` 表达持续的页面恢复状态，可同时提供重载和导出，按真实状态关闭或保留；它不进入全局 Toast 白名单，但遵守相同的鼠标、键盘和标题栏命中规则。
- 全局 NoticeBar 固定在当前应用视口顶部居中，不随 Canvas 或 HTML 页面滚动；N5 中断继续使用现有 `className="toast"`，不新增卡片或红字。持久化的内容安全问题留在工作区横幅，用户不能把真实风险关掉。
- 顶部 NoticeBar 覆盖 macOS 可拖动标题栏时，整条提醒必须是可点击的非拖动区域；鼠标、键盘都能操作同一个关闭按钮及真实恢复动作。
- 任何覆盖可拖动标题栏的 Renderer 浮层，遮罩和可操作区域都必须退出拖动命中区。原生 `<dialog>` 打开时立即建立安全默认焦点，不能用下一帧聚焦打断已开始的鼠标点击；关闭、`Escape` 与遮罩行为以各自流程合同为准。
- 普通控件状态不进入全局中断。
- 鼠标停留或键盘焦点进入提示时暂停计时，离开后从剩余时间继续。
- 文案：标题说明发生了什么；正文只说明结果和下一步，不展示 IPC、异常类、runtime-state、Hash 等内部词。
- 操作按钮必须改变失败条件或指向现有入口。不得为删除 Notice 发明局部错误区。
- 已登记项目的“当前稿”打开失败只报告当前稿未打开及原页面保留，不用“重新选择”跳到新项目文件选择器。选择器路径的按钮明确写“选择 HTML”；已准备但确认未完成的外部打开才显示“继续打开”，继续同一请求。
- NoticeBar 统一使用礼貌的 `status / polite` 通知；视觉上的错误色不抢断屏幕阅读器正在播报的主流程。

## 恢复责任

业务流程必须先决定由谁完成下一步，再决定是否显示 NoticeBar：

- 系统能安全处理：自动处理，不提醒。
- 当前控件或面板能解释：留在原位置。
- 持续内容风险：`WorkspaceSafetyState`，占用现有工作区横幅。
- 外部不可见重大风险：封闭 `GlobalInterruption`。
- 不可逆变化：Confirmation。

不得再以 `direct-action` / `user-choice` / `background-result` 作为新增全局 Notice 的入口。历史遥测仍可识别这些 disposition 名。

## 自动恢复边界

- 安全读取、状态轮询和附件读取遇到一次瞬时失败时，系统先自动重试；成功后不显示任何提示。Finder 展示、在默认浏览器打开、显示 Request 目录和显示历史 Version 文件属于用户发起的本地外部副作用：一次点击只发起一次调用，失败后不自动重放，原入口保持可用，只有新的用户点击才会再次调用。
- 关闭边界按冻结 HTML 的真实字节 Hash 与已确认 revision 复核，不要求 Canvas 临时 Hash、持久化 revision 等内部投影逐字相等。投影落后时先静默修正；仍无法证明时才限时回读磁盘，内容一致就自动收口。只有回读确认外部内容不同或内容完整性校验失败时，才保留导出、重新载入或重新打开入口。
- AI 状态轮询的短暂失败完全留在后台，由下一轮轮询继续，不累计成“重试”类提醒。只有整个项目资料服务已不可用，用户当前确实无法继续时，才显示持久恢复入口。
- 写入、发送、取消和冲突选择不得盲目自动重复。网络结果未知时，先读取权威状态或文件回读确认；已经成功则直接收口，仍未知则保持 fail-closed 并继续自动核对。
- 画布输入尚未完成、`PROJECT.md` 保存失败、附件预览失败等有明确局部位置的问题，优先在画布、编辑器、附件卡片或对话侧栏说明，不升级为全局 Toast。评论持久化失败会影响发送和离开安全，且评论栏可能已收起，因此使用唯一的工作区顶部持久横幅；评论栏底部不再重复。
- `PROJECT.md` 在停止输入约 700ms 后自动保存；规则页支持 `⌘S` 立即保存，切换项目或关闭应用时先完成这次保存。规则事实仍由 ProjectRulesWorkflow 持有，用户通过左侧固定的“长期规则”入口进入唯一规则标签页；保存状态留在编辑器原位，不升级为全局 Toast。
- 评论输入只保留一条未保存草稿；关闭输入框会收起并保留，切换项目和关闭应用不会丢失。用户在保存前尝试新建另一条评论或发送本轮要求时，系统阻止当前动作，并直接提供“继续填写”返回原草稿；点击“评论”保存后仍可继续修改。
- 浏览器预览是正式的只读产品能力：可以运行页面自身的脚本和交互，但不能编辑 HTML、添加评论或发起 AI；页面内操作不会保存。
- 多行粘贴与 Enter 在当前结构可安全映射时按普通编辑处理，不额外提醒。只有实际无法精确写回源码时，才显示统一的编辑受阻说明。
- 历史版本只用于只读查看及在 Finder 中定位，不提供“设为当前 HTML”或同义回写入口。

## 错误闭环

提醒不是流程终点。每个会阻止用户继续的状态，都必须在原位置保留原因与至少一条真实可执行路径：

- 可安全重复的读取和附件操作先自动恢复；仍失败时在原入口旁或短暂后台结果中说明，用户可从原入口再次发起，不额外提供同义重试按钮。Finder、默认浏览器、Request 目录和历史 Version 文件等本地外部动作不属于自动恢复范围；其第一次失败后等待用户从保留的原入口重新发起。
- 浏览器打开非 UTF-8 HTML 时，明确说明原文件未修改，并提供“重新选择”；提示不自动消失。
- 空文件、超过 25 MB 或超出 10 个上限的附件必须明确说明哪些没有加入；同批有效附件继续保留。仍有容量时提供“选择附件”，容量已满时提供“查看附件”并引导先移除一个，不能在浏览器预览路径静默返回。
- 画布直接编辑受阻时提供“添加评论”；源码映射无法建立时提供“重新载入”，不能只告诉用户失败原因。
- 项目切换遇到任务准备、附件上传、画布核对、规则自动保存或新修改写入等短暂状态时，保留目标项目并在状态结束后自动继续；当前内容不安全时提供“导出当前 HTML”并在问题解决后继续原操作。
- 显式全局评论按没有 `visualHint` 的稳定 `body + module` 语义识别；运行时评论即使使用 `body` 安全锚点也保留具体视觉对象的标题和位置。旧记录缺少运行时 `tagName` 时自动标准化为 `exact`，不得要求用户重新选择“整个页面”。
- 真正失联的局部评论继续保留评论与附件；卡片标注位置已丢失，并建议删除后在正确位置重新评论。发送入口切回编辑并高亮第一条失联评论，不显示全局重新定位卡片，也不自动继续发送。
- AI 返回 `error` 或 `no-change` 时解除画布锁定，对话侧栏只提供“返回编辑”。退出不自动打开评论；标题栏“上轮处理”可再次打开同一终态，重启后也能恢复。
- Request 发送结果未知时保持 fail-closed，并自动读取权威运行态；面板只说明系统正在核对，不提供“立即核对”或“重新打开源页”这类重复动作。只有项目资料服务本身确认不可用时，才在工作区横幅提供导出与重新打开。
- 剪贴板已完成 AI 交接时，结束本轮先用简短确认说明“源页不能自动停止 AI Agent”；安全按钮默认聚焦。确认后立即恢复编辑，并用一次 8 秒后台结果提醒用户手动停止仍在运行的 AI Agent。迟到 finalizer 返回不可重试的取消终态，不伪装成保存或路径错误。
- 当前 Bridge 明确托管的 Qoder ACP 会话不显示外部 Agent 风险确认；原位按钮显示“停止 Qoder 并继续编辑”，并在 Bridge 先关闭 ACP mutation surface、有界停止进程组、再持久取消 Request 的整个顺序中保持画布锁定。Bridge 崩溃后，处理中 Request 显示不可重试的“Qoder 会话已中断”，只提供结束旧 Request 并返回编辑；因为无法证明旧进程已经退出，结束前使用保守的外部 Agent 风险确认，durable cancel 只作为 authority fence，不声称已经停止旧 Qoder。
- `PROJECT.md` 读取失败时不显示伪造的可编辑正文，也不把错误文案标成“已保存”；原位置提供“重试读取”和“返回项目”。写入结果未知时先回读文件，内容已经一致即视为成功，否则在编辑器下方保留错误。
- 候选检查不展示内部代码或原始英文异常。普通文字、属性、结构、样式、脚本、inline handler、可执行 URL 或 refresh 指令的变化都不按内容阻断，也不产生检测提示；连续性证据不足时提示“页面变化较大”并强制先审阅。身份、协议、路径、Hash、完整文档和可显示 body 仍然停止提交。
- 历史 Version 或已归档终态遇到带有或省略退役可执行评估字段的 Developer Preview 形态时，系统核对冻结/封存 HTML 与 Hash 后静默按当前文档健康与连续性规则重算，在内存中移除旧字段和脚本结论。归档结果不被复活；不显示“读取超时”，也不因辅助历史展示记录禁用当前权威 HTML 的编辑。

所有 Renderer → Bridge 请求都有超时边界。普通读写 15 秒，附件 30 秒，建立 AI Request 60 秒；超时后必须释放按钮忙碌态，并进入上述可恢复路径。关闭时的补充源文件回读使用更短的有限预算，失败后保持当前页面并在下次关闭继续核对，不把一次复核失败描述成“内容没有保存”。Bridge 意外停止时，当前窗口内容保持可导出：Renderer 已加载时只显示应用内持久恢复入口；只有 Renderer 尚不可用、关闭确认超时或关闭协调本身异常时才使用原生对话框，不能两处同时询问同一个决定。重新打开前仍执行关闭写入检查，未安全写入时要求先导出或处理，不能直接丢弃内存内容。

产品错误文案优先由稳定错误码映射。未知消息在展示前会剥离 IPC/异常类前缀，并屏蔽本地路径、项目/文档 ID、Hash、`pendingWrite` 等内部字段和纯英文技术异常；无法确定安全文案时使用该流程的中文兜底说明。

## 首次启动

仅启动 App、浏览最近文件或展开左侧项目上下文不创建空的项目记录目录。用户第一次真正编辑、添加附件/评论或发送 AI Request 时，才创建：

`~/Documents/Stemmio/项目记录`

桌面不再探测 `PageRootV2`、`YuanYe` 或 `HTML AI 工作台` 的项目记录目录，
也不再打开这些旧 appData 名下的 `html-projects.json`。Recent 只读当前
`userData` 状态文件。`STEMMIO_WORKSPACE` 仍可作为测试覆盖；否则只使用
上述 Stemmio 路径。旧目录不会被删除。v4 项目文件在
`~/Documents/Stemmio/项目`。

macOS 首次授予 `Documents` 访问权限时，Bridge 子进程可能在系统权限面板
处暂停。12 秒只作为“启动较慢”的内部观察点，不是失败截止时间；只要进程
仍然存活，主进程继续等待同一个启动操作，权限选择完成并收到 `ready` 后
自动继续。等待期间不弹“启动超时”、不退出，也不发布未就绪端口。只有
Bridge 在 `ready` 前退出或报告进程错误时，才显示一次原生启动失败提示。

## 再次启动

应用尝试恢复上次当前 HTML 和它的运行态。若上次文件存在，恢复当前项目、评论、编辑状态、AI 处理状态或“最新版可打开”状态；若文件移动、删除、无权限或内容损坏，明确显示原因，并提供“选择其他 HTML”，不会静默回到欢迎页假装恢复成功。
