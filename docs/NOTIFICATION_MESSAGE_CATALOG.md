# 源页提醒消息全量台账

> 行为基线：当前源码实现。
>
> 统计日期：2026-09-01。
>
> 目的：让产品、设计、开发和测试都能回答四个问题——为什么发生、为什么要提醒、用户该做什么、系统为什么不能自己处理。

## 0. Notice 增长已冻结

从本版本起，业务代码不得新增自由 `setToast({...})`、新的 `<NoticeBar`、
`background-result` 或 `uncatalogued` 出口。通用 `setToast` 已退休；允许存在的
极少数中断只能通过 `setInterruption({ kind })` 进入
`globalInterruptionPresentation()`。例外只能写在
`scripts/notice-disposition-ledger.json`。

处置分类：

| 类 | 含义 | 后续 PR |
| --- | --- | --- |
| N0 | 直接删除。结果已经可见，或用户不需要知道。 | PR-B 已完成 |
| N1 | 系统静默恢复。内部可靠性问题，成功后无感。 | PR-C 已完成 |
| N2 | 只复用现有控件行为。失败时保持当前状态。 | PR-D 已完成 |
| N3 | 迁入工作区级持续风险横幅，不再走 Toast。 | PR-E 已完成 |
| N4 | 不可逆确认。继续走受控确认，不走 Notice。 | 已由 PR #386 收口 |
| N5 | 临时白名单。没有现成反馈位置，不得为删除而发明新 UI。 | PR-E 已收成封闭 GlobalInterruption；保留 11 条 |

规则：

- 当前数量是基线；后续 PR 只能下降。
- 修改现有 Notice 必须同时改分类或删除。
- 白名单只允许减少。
- 不得用包装函数绕过检测。
- 清理 Notice 时不得新增局部错误卡片、红字、徽标或新横幅。

活台账和 N5 退出条件以 `scripts/notice-disposition-ledger.json` 为准。本文保留历史消息解释，不再作为可以新增提醒的许可。

## 1. 先说结论

源页目前不是“发生错误就弹提醒”，而是先判断下一步归谁负责：

1. 系统能安全处理：自动处理，不提醒。
2. 当前控件或面板能解释：留在原位置，不弹全局提醒。
3. 用户必须改变一个外部条件：显示全局操作提醒。
4. 用户必须在多个安全结果中作决定：显示全局选择提醒或原位决策面板。
5. 结果发生在后台项目，当前页面没有其他可见入口：显示后台结果提醒。
6. 操作会舍弃内容、替换当前 HTML 或覆盖关键选择：使用确认弹窗。
7. Renderer 尚不可用、关闭确认超时或关闭协调本身异常：才使用 macOS 原生提示。

最重要的判断不是“错误严不严重”，而是“用户现在是否真的需要做事”。错误级别、红色样式、`sticky` 或按钮本身，都不能自动获得打扰用户的资格。

## 2. 统计口径

源页只回传提醒的稳定编号、tone、disposition、surface、是否有操作按钮
以及 action/dismiss/auto-dismiss 结果；不会回传标题、正文、动态路径、
文件名或错误消息。Canvas 提醒使用 `canvas_c01` 与 `canvas_c12` 稳定
原因码；`canvas_c02_edit_blocked`、`canvas_c05_complex_structure`、
`canvas_c06_special_layout`、`canvas_c09_structure_delete`、
`canvas_c10_ime_incomplete` 与 `canvas_c11_target_drift` 已随编辑受阻
提示一起移除，`canvas_c03_style_boundary` 与 `canvas_c04_empty_formatting`
也不再作为进入或输入的拒绝原因；未进入台账的动态消息统一降为 `uncatalogued`。
提醒统计只用于判断哪些流程真正打断用户，不改变本台账的显示准入规则。

### 2.1 本文包含什么

- Canvas 顶部的全局 `NoticeBar`。
- Canvas 内部的编辑受阻 `NoticeBar`。
- 评论栏、AI 对话侧栏与设置页里的原位提醒与决策。
- Renderer 确认弹窗。
- Electron/macOS 原生提示。
- 保存、锁定、剪贴板和 AI 流程等持续状态。
- 代码中仍保留、但会被当前策略过滤而不显示的消息定义。
- 系统自动恢复、因此正常情况下不显示消息的场景。

### 2.2 本文不包含什么

- 普通按钮名称、输入框帮助文字和空状态，除非它们承担恢复或状态说明。
- 文件选择器、保存位置选择器本身；它们是用户主动打开的系统工具，不是提醒。
- 开发环境错误浮层、控制台日志、IPC 原始错误和测试框架输出；它们不是正式产品界面。
- 操作系统、GitHub、QoderWork 或其他外部产品自行显示的消息。

### 2.3 当前静态统计

| 项目 | 数量 | 如何理解 |
| --- | ---: | --- |
| `setToast(...)` 创建调用 | 0 | 通用 `setToast` 已退休 |
| 仅用于清除当前消息 | 无 | 中断关闭走 `setInterruption(null)` |
| N0 待删除成功/可见结果 | 0 | PR-B 已删除成功提示与自动恢复成功 |
| N1 内部静默恢复 | 0 | PR-C 已补齐一次重试/回读并删除内部 Notice |
| N2 复用现有控件 | 0 | PR-D 已删除；失败时保持当前状态或聚焦现有入口 |
| N3 工作区持续风险 | 0 | PR-E 已迁入现有危急横幅；不再走 Toast |

## 3. 消息出口与样式

### 3.1 全局 NoticeBar

出现位置：应用视口顶部导航下方、Canvas 可视区域中央；使用
viewport-fixed 定位，不随 HTML 页面滚动，不遮挡右侧评论栏。

当前视觉参数：

- 最大宽度 `520px`，窄屏时左右至少保留 `12px`。
- 最小高度 `68px`，圆角 `15px`。
- 白色半透明渐变背景，`22px` 背景模糊，带轻微饱和度和内高光。
- 标题 `13px`，正文 `12px`，操作按钮 `11.5px`。
- 图标区域 `32 × 32px`，操作按钮和关闭按钮最小高度 `32px`。
- 成功为绿色，普通信息为紫色，警告为金棕色，错误为红色。
- 进入动画约 `160–200ms`；用户启用“减少动态效果”时取消动画。
- 鼠标悬停或键盘焦点进入后暂停自动消失。
- 统一使用 `role="status"`、`aria-live="polite"` 和 `aria-atomic="true"`，不抢断屏幕阅读器正在播报的主流程。

显示时长：

- `direct-action`、`user-choice`、错误或 `sticky`：持续显示，直到用户处理或关闭。
- `background-result`：通常 8 秒；若本身是错误或 `sticky`，则持续显示。
- 普通警告理论值为 6 秒、普通成功/信息为 3.5 秒，但未显式准入的消息不会进入全局 NoticeBar。

### 3.2 Canvas 内编辑提示

与全局 NoticeBar 使用同一组件和视觉语言，并提升到应用视口固定层。
普通编辑受阻提示 5 秒后自动消失；源码映射完全失败时持续显示。它
不会因用户滚动到页面下方而藏在文档顶部，也不会遮挡评论栏或改变
当前文字位置。

### 3.3 原位提醒与流程面板

适用于“问题属于哪个控件，就在哪里解释”的场景，例如：

- 评论记录失败：使用唯一的工作区顶部持久横幅；评论栏可能已收起，不在其底部重复。
- `PROJECT.md` 保存失败：留在规则编辑器下方。
- AI 状态核对：留在 AI 对话侧栏或设置页。
- 外部文件冲突：留在 Canvas 上方的持久横幅。

原位提醒没有统一倒计时。只要真实问题还存在，它就保留；问题解除后随状态一起消失。

### 3.4 确认弹窗

只用于“继续会产生明确不可逆或易误解结果”的操作。按钮必须对应两个真实结果，不能把普通错误包装成确认弹窗。

### 3.5 macOS 原生提示

只在 Web Renderer 不能承担恢复、关闭确认超时、关闭协调本身异常，或者应用根本无法启动时使用。Renderer 已知并能留住恢复入口的关闭阻断只返回当前页面；同一问题不会同时显示 Renderer 横幅和原生弹窗。

## 4. 系统如何决定是否提醒

```text
发生异常或状态变化
  ├─ 能否安全自动恢复？
  │    └─ 能：自动重试、回读或继续核对，不提醒
  ├─ 当前控件/面板是否已经能说明？
  │    └─ 能：原位显示，不弹全局提醒
  ├─ 用户是否必须改变一个条件？
  │    └─ 是：direct-action
  ├─ 用户是否必须从多个安全结果中选择？
  │    └─ 是：user-choice / 原位决策面板
  ├─ 是否是其他项目的后台结果？
  │    └─ 是：background-result
  ├─ 继续是否会舍弃或替换内容？
  │    └─ 是：确认弹窗
  └─ Renderer 是否不可用？
       └─ 是：macOS 原生提示
```

## 5. 自动处理、正常不提醒的场景

### A01. 一次性的读取失败

- 用户刚做了什么：打开附件、在 Finder 显示文件，或系统读取状态。
- 系统发现什么：第一次读取遇到超时、临时连接失败或可重试状态码。
- 系统怎么做：GET/HEAD 请求自动再试一次，间隔约 `180ms`。
- 用户要做什么：什么都不用做。
- 为什么不提醒：一次瞬时失败没有形成用户问题，弹出消息只会制造噪音。
- 小白案例：像网页偶尔“卡了一下”，系统自己再读一次就成功，不需要你点“重试”。

### A02. AI 状态轮询偶发失败

- 用户刚做了什么：已经发送一轮要求，正在等待 AI 返回。
- 系统发现什么：某一次状态查询没有响应。
- 系统怎么做：下一轮继续自动查询，不累计次数，也不把暂时失败升级成用户提醒。
- 用户要做什么：无需操作。
- 为什么不提醒：AI 任务可能仍在正常运行，单次轮询失败不等于任务失败。
- 小白案例：快递查询页面一瞬间没刷新，并不代表包裹丢了。

### A03. Request 提交结果未知

- 用户刚做了什么：点击“发给 AI”。
- 系统发现什么：请求可能已经建立，但客户端没有收到明确答复。
- 系统怎么做：画布保持只读，后台读取权威工作区状态；不重复发送同一轮要求。
- 用户要做什么：等待自动核对。只有工作区本身明确不可用时，才从工作区横幅导出或重新打开源页。
- 为什么不直接重试提交：原样重试可能建立两份重复任务。
- 小白案例：付款页面转圈时，先查订单是否已经生成，不能再次扣款。

### A04. `PROJECT.md` 自动保存与写入结果未知

- 用户刚做了什么：修改项目规则后停下输入、关闭规则页或切换项目。
- 系统发现什么：写入请求报错或超时，无法仅凭响应判断是否已成功。
- 系统怎么做：停输约 700ms 后自动保存；结果未知时重新读取 `PROJECT.md`，内容已经一致就直接视为成功。
- 用户要做什么：通常无需操作；只有回读后仍不一致，才在原编辑器点“再次保存”。
- 为什么不弹全局提醒：保存由系统负责，错误也有明确的原位入口。
- 小白案例：记事本自动保存时网络闪断，系统先核对文件，已经写进去就不再吓你。

### A05. 旧版全局评论缺少运行时字段

- 用户刚做了什么：打开旧项目或发送旧评论。
- 系统发现什么：评论没有 `tagName`，但稳定的 `body + module` 身份仍能证明它是整个页面。
- 系统怎么做：自动标准化为可用目标。
- 用户要做什么：什么都不用做。
- 为什么不提醒：这是已知数据兼容问题，系统有确定答案，不应把迁移工作交给用户。
- 小白案例：旧通讯录没存“国家”字段，但号码格式足以确定是中国号码，系统自动补全。

### A06. 已有一条未保存评论

- 用户刚做了什么：准备在另一个位置写评论，但已有一条未发送草稿。
- 系统发现什么：草稿仍完整存在。
- 系统怎么做：保留原草稿和附件，阻止建立第二条草稿或发送本轮要求，并把用户带回原输入。
- 用户要做什么：在原输入框点击“评论”保存；保存后仍可修改，然后继续添加下一条。
- 为什么不弹全局提醒：未保存草稿入口、评论栏卡片和原输入框已经说明同一件事。
- 为什么不自动保存或允许多条草稿：点击“评论”是用户确认这条要求进入本轮的明确边界；单一未保存状态更容易理解，也避免发送前再管理一组半成品。
- 小白案例：填写一条待办时，先确认保存当前内容，再新建下一条；保存不等于已经发送给 AI。

### A07. 项目切换遇到短暂流程占用

- 用户刚做了什么：AI 提交、附件上传、规则保存、画布核对或自动保存过程中选择另一个项目。
- 系统发现什么：当前操作还未结束，但没有需要用户决定的问题。
- 系统怎么做：记住目标项目；操作结束后自动打开。
- 用户要做什么：等待当前步骤完成。
- 为什么不弹提示：下一步仍由系统负责，用户没有新的动作。
- 小白案例：电梯门正在关闭，你按了下一层，系统记住指令，门关好后自动运行。

### A08. 评论数量超过 100

- 用户刚做了什么：继续添加大量评论。
- 系统发现什么：评论数量很多。
- 系统怎么做：保留全部评论；超过 40 条后使用虚拟化渲染。
- 用户要做什么：照常工作。
- 为什么不提醒或阻止：条数本身不是错误，性能问题由渲染策略解决。
- 小白案例：通讯录有 101 个联系人不该弹警告，只需要列表滚动仍然顺畅。

### A09. “已安全保存”后的关闭元数据漂移

- 用户刚做了什么：标题栏已经显示“已安全保存”，随后关闭窗口或退出应用。
- 系统发现什么：冻结 HTML 与源文件确认内容一致，但 Canvas 临时 Hash 或 revision 投影比当前确认状态旧。
- 系统怎么做：重新计算冻结 HTML 的真实 Hash；已确认 revision 大于或等于关闭 cutoff 即可。若本地投影仍不足，再限时回读源文件；字节一致就静默修正 Hash/revision 并继续关闭。
- 用户要做什么：什么都不用做。
- 为什么不提醒：这是内部投影同步问题，不代表用户误操作，也不代表文件未保存。
- 提醒门槛：只有权威回读确认磁盘 HTML 已被其他操作改动，或返回内容无法通过完整性校验时，才在应用内保留导出与重新载入/重新打开入口。
- 小白案例：存档柜已经放好文件，只是柜门上的状态标签慢了一拍；系统核对文件后直接修正标签，不要求用户处理。

## 6. 全局 NoticeBar：附件与评论

### G01. 附件选择期间关闭评论（已取消提醒）

- 用户触发：在选择或上传附件期间尝试关闭评论、切换项目或关闭应用。
- 系统条件：附件归档仍在进行。
- 当前行为：评论关闭按钮、项目切换和关闭流程会等待上传完成；完成后附件仍归属原评论或草稿。
- 用户操作：无需重新选择，也不会看到“附件没有加入”。
- 为什么不提醒：这是系统能够确定完成顺序的并发问题，不应让用户重复上传。
- 小白案例：照片仍在上传时，相册先把“离开”动作排队；上传完成后自动继续，而不是让你重新选照片。

### G02. 附件全部不符合要求

- 用户触发：一次选择了空文件、超过 25MB 的文件，或在已满 10 个附件时继续选择。
- 系统条件：本批次没有任何文件可以安全加入。
- 当前文案：标题“附件没有加入”；正文按实际情况组合，例如“已达到每条评论 10 个附件的上限，1 个未加入。请先移除一个附件，再重新选择。”
- 操作按钮：容量已满时“查看附件”；仍有容量时“重新选择”。
- 样式与时长：警告色、持久、`direct-action`。
- 用户操作：移除一个附件，或选择符合大小和内容要求的文件。
- 为什么提醒：失败条件只有用户能改变。
- 为什么不自动删除旧附件：系统不知道哪个旧附件更不重要。
- 小白案例：行李箱已经装满，系统可以告诉你超重，但不能替你扔掉一件衣服。

### G03. 部分附件没有加入

- 用户触发：一批文件中有些有效、有些为空、过大或超过数量上限。
- 系统条件：有效附件已保存，其他附件被拒绝。
- 当前文案：标题“部分附件没有加入”；正文列出失败原因，并明确“已加入的附件仍然保留”。
- 操作按钮：按剩余容量显示“查看附件”或“重新选择”。
- 样式与时长：警告或错误色；评论仍打开时持续显示。
- 用户操作：检查已加入列表，只补充缺少的文件。
- 为什么提醒：静默丢弃会让用户误以为整批都成功。
- 为什么不整批回滚：保留有效文件能减少重复操作。
- 小白案例：上传 10 张照片时 9 张成功、1 张过大，系统保留 9 张，只告诉你处理最后一张。

### G04. 浏览器只读预览中添加附件（入口已取消）

- 用户触发：使用纯浏览器预览。
- 系统条件：浏览器预览没有本地项目记录，并且产品边界明确为只读。
- 当前行为：编辑、评论、附件与“发给 AI”入口都不可用；顶部持续说明“浏览器预览 · 只读”“操作不会保存”。
- 用户操作：只需浏览和试用页面自身交互；需要修改时在桌面版打开本地 HTML。
- 为什么不弹提醒：不可用能力在入口处已经被禁用，不应等用户点击后再报错。
- 小白案例：展厅里的样机可以观看和试按，但没有“保存订单”按钮，也不会等你按完才说不能保存。

### G05. 添加附件时，项目资料没有建立成功（已取消提醒）

- 用户触发：选择附件。
- 系统条件：源页无法建立当前项目的受控记录目录。
- 当前结果：调用已删除，不弹出。附件选择器仍可再用。
- 实际反馈：有效附件没有加入；列表与选择器保持当前状态。
- 设计理由：现有选择器就是重试入口，不另造一条失败提醒。

### G06. 图片暂时无法预览（已取消提醒）

- 用户触发：点击图片缩略图。
- 系统条件：自动读取一次重试后仍失败。
- 当前结果：调用已删除，不弹出。灯箱不会打开。
- 实际反馈：缩略图仍在评论中，可再点预览。
- 设计理由：预览没出现本身就是结果；缩略图就是原入口。

### G07. 普通附件暂时无法打开（已取消提醒）

- 用户触发：点击文件附件。
- 系统条件：自动读取一次重试后仍失败。
- 当前结果：调用已删除，不弹出。下载不会开始。
- 实际反馈：附件条仍在评论中，可再点打开。
- 设计理由：没有下载本身就是结果；附件条就是原入口。

### G08. 删除元素会连同关联评论删除

- 用户触发：在画布结构工具条点击“删除元素”。
- 系统条件：删除目标或其任一源码后代存在当前 Working Copy 评论或未保存评论草稿。
- 当前文案：标题“删除‘目标名称’及其全部内容？”；有评论时补充“关联的 N 条评论也会一起删除。”；同时有未保存草稿时一并说明，只有草稿时显示“未保存的评论草稿也会一起删除。”
- 操作按钮：“取消”“删除元素”。
- 样式与时长：复用已有的元素删除确认弹窗，只在有关联评论或草稿时追加结果说明；不新增第二套确认交互，不自动消失。
- 用户操作：取消时页面和评论都不变；确认后按语义删除结果中的稳定 ID 集合批量删除元素、后代评论、草稿与草稿附件引用。
- 为什么提醒：删除元素不可逆，评论归属也随源码目标一起消失，必须在提交前一次说清结果。
- 小白案例：删除一整段批注过的内容时，先告诉用户这一段上的批注也会被删除。

### G09. 当前草稿目标无法安全定位

- 用户触发：正在填写评论时页面内容变化。
- 系统条件：草稿没有可验证的精确 `sourceAnchor`，或该源码锚点失去唯一性；运行时目标若仍有安全源码锚点，不因视觉匹配失败进入此流程。
- 当前文案：标题“评论目标无法安全定位”；正文“评论内容和附件仍保留；重新选择画布位置后即可继续。”
- 操作按钮：“重新选择目标”。
- 样式与时长：警告色、`user-choice`。
- 用户操作：重新点选 Canvas 位置。
- 为什么提醒：文字和附件可以保留，但目标不能由系统猜测。
- 小白案例：便签内容还在，但原来贴的那一行文字已经被改掉，需要你重新贴到正确位置。

### G10. 已有评论位置异常丢失

- 用户触发：点击、编辑或发送一条已有评论。
- 系统条件：`sourceAnchor` 解析为 `orphaned` 或 `ambiguous`；运行时目标的 `visualHint` 匹配失败但源码锚点安全时，评论仍降级显示在源码宿主。
- 当前文案：标题“评论位置已丢失”；正文“建议删除这条评论，并在正确位置重新评论。”
- 操作按钮：沿用评论卡片既有“删除评论”，不增加重新定位按钮。
- 样式与时长：卡片内警示说明，随评论持续存在；评论栏顶部不再出现全局恢复卡片。
- 用户操作：删除失联评论，再在正确位置创建新评论。发送被阻断时系统回到编辑画布并高亮第一条失联评论，不自动续发。
- 为什么提醒：系统没有唯一答案，猜错位置会把要求交给错误内容；重新评论能形成新的精确稳定 ID 关系。
- 小白案例：便签原来的粘贴位置已经丢失，保留便签内容但建议在正确位置重新贴一张。

## 7. 全局 NoticeBar：项目、文件与导出

### G11. 切换项目时，项目规则尚未保存（改为自动保存）

- 用户触发：修改 `PROJECT.md` 后打开另一个项目。
- 系统条件：规则编辑器内容与磁盘内容不同。
- 当前行为：系统先自动保存并回读核对；成功后直接打开目标项目。只有确认保存失败时，规则编辑器原位显示“再次保存”。
- 用户操作：正常情况下无需操作，也不会看到全局提醒。
- 为什么不再让用户选择保存或放弃：用户已经通过编辑表达了保留意图；默认保存是可逆且符合主流程的动作，“还原修改”仍留在规则页。
- 小白案例：云文档切换页面前先自动保存，不会每次都问“要不要保存”。

### G12. 切换项目时，当前 HTML 正在写入（改为延后并自动继续）

- 用户触发：自动保存或画布核对过程中切换项目。
- 系统条件：当前写入还没有得到确定结果。
- 当前行为：系统记住目标项目，完成写入与回读核对后自动继续；不弹“当前 HTML 还没有更新成功”。
- 用户操作：无需再次点击目标项目。只有写入最终进入持久冲突或失败横幅时，才从横幅导出当前 HTML 或重新载入。
- 为什么不提醒：短暂的“正在写”不是失败，用户此时没有额外动作。
- 小白案例：文件正在复制时，系统排队执行“打开下一项”，不要求你反复点。

### G13. 切换项目时，评论正在记录（改为延后并自动继续）

- 用户触发：评论持久化或附件上传过程中切换项目。
- 系统条件：当前记录尚未完成。
- 当前行为：系统保留目标项目，等待评论记录和附件归档完成后自动继续；评论草稿也同步保存在本地恢复记录中。
- 用户操作：无需手动“重试记录评论”。若自动恢复后仍确认失败，工作区顶部唯一横幅提供重试，评论栏不重复。
- 为什么不提醒：只要系统仍能完成当前写入，就不应把内部时序变成用户任务。
- 小白案例：聊天附件还在上传时切换会话，应用先传完再离开，不让你重新操作。

### G14. 无法打开选中的 HTML

- 用户触发：从文件选择器或最近打开列表打开 HTML。
- 系统条件：文件移动、删除、损坏、无权限或暂时不可读。
- 当前文案：标题“无法打开这个 HTML”；正文按来源说明“文件可能已移动……”。
- 操作按钮：最近记录为“重新选择位置”，普通打开为“重新选择”。
- 样式与时长：错误色、持久、`direct-action`。
- 用户操作：选择文件的新位置，或从最近打开列表移除旧记录。
- Finder / Open With / 启动参数打开失败：错误显示在侧栏“打开 HTML”旁，不再弹出系统错误框；内部详情只写日志。
- 为什么提醒：系统无法知道文件搬到了哪里。
- 小白案例：桌面快捷方式指向的文件被移动，需要你告诉应用新地址。

### G15. 文件编码或类型不支持

- 用户触发：在浏览器预览路径选择文件。
- 系统条件：文件不是 `.html/.htm`，或不是 UTF-8。
- 当前文案：
  - 编码问题：“文件编码不支持”“原文件没有被修改。请先转换为 UTF-8，再重新选择。”
  - 类型问题：“文件无法打开”“请选择 .html 或 .htm 文件后重试。”
- 操作按钮：“重新选择”。
- 样式与时长：警告色、持久、`direct-action`。
- 用户操作：转换编码或选择正确文件。
- 为什么提醒：自动转码可能改变原文件字节，违背源码保真。
- 小白案例：应用只接受指定格式，不能为了“帮忙”就擅自改写原文件。

### G16. 无法在文件夹中打开当前源 HTML

- 用户触发：点击当前项目的“在文件夹中打开”。
- 系统条件：自动尝试后仍无法显示，文件可能已移动。
- 当前文案：标题“无法在文件夹中打开”；正文默认“源 HTML 可能已移动；当前项目仍保持打开，可以重试。”
- 样式与时长：警告色、`background-result`、8 秒。
- 用户操作：稍后从原“在文件夹中打开”按钮再次尝试。
- 为什么提醒：当前项目仍可用，问题只影响辅助查看。
- 小白案例：文件还在应用里打开，只是“在文件夹中打开”没有成功，不应阻断编辑。

### G16b. 已导入 Stemmio（仅废纸篓失败）

- 用户触发：确认把一份全新外部 HTML 导入，并要求把原文件移入废纸篓。
- 系统条件：导入已成功，但原文件未能移至废纸篓。成功导入不再提示。
- 当前文案：标题“已导入 Stemmio”；正文“已保存为 `<V1 文件名>`，原文件未能移至废纸篓，仍留在原来的位置。”
- 操作按钮：“在文件夹中打开”。
- 样式与时长：警告色、`background-result`。N5 白名单 `import-trash-failed`。
- 用户操作：可在 Finder 核对该原文件是否还在。
- 为什么提醒：用户明确要求删除原文件，但结果无法从现有界面判断。
- 小白案例：你勾了丢掉原件，系统却没能丢掉，必须说一声。

### G16c. 导入后画布确认失败（已取消提醒）

- 用户触发：确认导入或打开之前的项目后，新画布没有在时限内确认载入目标 HTML。
- 系统条件：`DocumentSession.canvasAuthority` 对该 generation/Hash 标记失败。
- 当前结果：调用已删除，不弹出。工作流会自动重试一次画布确认；仍失败则回滚导入确认、保留原稿，不发明替代 UI。
- 实际反馈：页面保持确认前状态；内部失败只记日志。
- 设计理由：瞬时 Canvas ACK 是内部可靠性问题，用户已经看到当前页面是否打开。

### G16d. 确认期间外部 HTML 被修改

- 用户触发：首次导入确认框仍打开时，磁盘上的这份外部 HTML 内容变了，然后点击“导入并打开”。
- 系统条件：再次读取的 Hash 与准备确认时不同。
- 当前文案：标题“无法打开这个 HTML”；正文“文件在确认期间被修改，没有导入。”
- 操作按钮：“重新选择”。
- 样式与时长：错误色、持久、`direct-action`。
- 用户操作：重新打开该文件；原稿和当前项目都没有改变。
- 为什么提醒：确认框看到的内容已经不是即将导入的字节。
- 小白案例：对话框开着时别人改了这份网页，不能按旧内容悄悄导入。

### G16a. 当前 HTML 重命名失败（文件名原位）

- 用户触发：单击顶部文件名或铅笔图标，输入新名称后按 `Enter` 或移开焦点。
- 系统条件：名称非法、同目录已有同名文件、源 Hash 已变化、权限不足，或安全保存边界没有完成。
- 当前文案：直接显示具体原因；默认“文件名没有修改，请检查名称后重试。”
- 位置：文件名输入框正下方；输入框保持打开并重新获得焦点。
- 用户操作：修改名称后再次提交，或按 `Escape` 保留原文件名。
- 为什么不使用 Toast：失败对象就是仍在编辑的文件名；把错误移到全局会割裂输入与修正动作。
- 小白案例：表单中的用户名重复时，应在用户名输入框旁说明，不应在页面另一角弹提示。

### G17. 项目记录目录暂时无法打开

- 用户触发：点击打开项目记录目录。
- 系统条件：自动尝试后 Finder 仍未打开。
- 当前文案：标题“项目记录暂时无法打开”；正文“项目记录仍保留在本地，可以重新尝试。”
- 样式与时长：警告色、`background-result`、8 秒。
- 用户操作：稍后从原入口再次打开。
- 为什么提醒：只是辅助导航失败，不代表记录丢失。
- 小白案例：文件柜抽屉暂时拉不开，但柜内文件并没有消失。

### G18. HTML 副本没有导出

- 用户触发：点击“导出 HTML 副本”并选择位置。
- 系统条件：写入失败、目标位置不可用，或需要重新选位置。
- 当前文案：标题“副本没有导出”；正文保留具体原因，并明确“当前源 HTML 没有被改动。”
- 操作按钮：“重新选择位置”。
- 样式与时长：错误色、持久、`direct-action`。
- 用户操作：选择其他文件夹或文件名。
- 为什么提醒：导出是用户明确期待的结果，失败后必须给可改变条件的路径。
- 小白案例：打印机没纸时，需要换纸，而不是反复按同一个打印按钮。

### G19. 重新载入外部文件失败（已取消提醒）

- 用户触发：在非冲突状态下点击重新载入磁盘内容。
- 系统条件：安全读取自动重试后仍失败。
- 当前结果：调用已删除，不弹出。当前内容保持不变。
- 实际反馈：冲突横幅或重新载入入口仍在。
- 设计理由：页面没变成磁盘版本，用户已经看到结果。

### G19a. 无法预览外部版本（已取消提醒）

- 用户触发：冲突横幅中点击“预览外部版本”。
- 系统条件：只读 `/source-preview` 读取失败或 Hash 不一致。
- 当前结果：调用已删除，不弹出。预览不会打开。
- 实际反馈：冲突横幅仍在，可导出或采用磁盘版本。
- 设计理由：预览没出现本身就是结果。

### G19b. 项目已解锁（已取消提醒）

- 原问题：force-unlock 成功后弹出“项目已解锁”。
- 当前行为：冲突横幅消失，画布回到可编辑；不再额外提示。
- 为什么取消：解锁结果已经能从现有冲突状态消失和可编辑画布直接看到。

### G19c. 采用磁盘版本失败（已取消提醒）

- 用户触发：确认采用磁盘版本后后端未能解锁。
- 当前结果：调用已删除，不弹出。项目仍保持冲突状态。
- 实际反馈：冲突横幅仍在，可先导出当前 HTML 再试。
- 设计理由：解锁没发生，现有冲突状态已经说明结果。

### G20. 外部差异按钮（已取消）

- 原问题：冲突横幅提供“查看差异”，读取失败后又提示用户重试同一动作。
- 当前行为：冲突横幅只保留真正改变结果的路径——导出当前 HTML、预览外部版本、采用磁盘版本；不再提供临时差异读取与对应失败提醒。
- 为什么取消：辅助比较不是解除冲突的必要条件，额外入口制造了新的失败分支。
- 小白案例：真正需要决定的是保留哪份文件；打不开一张临时对照图，不应再形成一层错误流程。

### G21. AI 冲突比较按钮（已取消）

- 原问题：AI 冲突面板提供“比较两份内容”，比较失败后只能要求用户再次比较。
- 当前行为：面板直接说明两份内容都已保留，底部提供“采用 AI 版本”与“保留外部版本”两个真实结果。
- 为什么取消：它不是恢复动作，且失败只会形成循环；候选文件仍可从受控记录中审计。
- 小白案例：系统把两份合同都保存好，并直接问你最终采用哪份，不再额外依赖一个可能打不开的比较弹窗。

## 8. 全局 NoticeBar：AI 提交、后台结果与历史版本

### G22. 项目记录尚未建立，不能发送（已取消提醒）

- 用户触发：点击“发给 AI”。
- 系统条件：提交前无法建立或核对项目记录，或其他发送失败。
- 当前结果：调用已删除，不弹出。发送没有执行。
- 实际反馈：发送按钮仍可点击；内部失败只记日志。
- 设计理由：现有发送入口就是重试位置，不另造一条失败提醒。

### G23. 本轮 Request 明确没有提交（改为处理面板结果）

- 用户触发：点击“发给 AI”。
- 系统条件：明确确认 Request 未建立；这与“结果未知”不同。
- 当前行为：画布恢复编辑，本轮处理面板显示“本轮没有改动当前 HTML”和具体原因；底部只提供“返回编辑”。
- 用户操作：在同一个流程面板查看原因后返回编辑；需要时自行打开评论修改。终态可从“上轮处理”再次查看。
- 为什么改为原位：错误与本轮要求、冻结内容和处理步骤需要一起阅读。
- 小白案例：银行明确显示“转账未发起”时可以重试；若只是不知道结果，则必须先查流水。

### G24. 其他项目的新版本已生成（已取消提醒）

- 用户触发：在一个项目等待 AI 后切换到了另一个项目。
- 系统条件：后台项目生成并安全提交了候选版本。
- 当前结果：调用已删除，不弹出。
- 实际反馈：最近项目列表标记“新版本可查看”；协议异常只记内部日志。
- 设计理由：列表已经是持续状态来源，成功结果不需要全局打断。

### G25. 其他项目的新版本可以打开

- 用户触发：在别的项目工作时，后台 AI 完成校验。
- 系统条件：候选版本已安全保留，等待用户打开。
- 当前反馈：最近项目列表标记“新版本可查看”；不再弹出“可以打开了”。
- 用户操作：选择是否切回。
- 为什么提醒：结果完成，但不替用户中断当前工作或自动替换画布。
- 小白案例：另一个下载任务完成，只给通知，不抢走当前窗口。

### G26. 其他项目没有生成新版本（不弹全局消息）

- 用户触发：后台项目的 AI 返回 `no-change`。
- 系统条件：没有可采用的内容变化。
- 当前反馈：最近项目列表标记“已完成 · 无变化”。
- 用户操作：不需要处理；若仍想修改，再切回调整评论。
- 为什么不提醒：这是正常完成结果，持续列表状态已经足够。
- 小白案例：后台任务完成但发现无需更新，告知结果即可。

### G27. 其他项目处理失败（改为项目状态）

- 用户触发：后台项目的 AI 返回错误。
- 系统条件：硬校验、协议或处理失败，源 HTML 未覆盖。
- 当前反馈：最近项目列表标记“需要处理”；完整原因保留在该项目的本轮处理面板。
- 用户操作：方便时切回项目查看。
- 为什么不弹全局错误：最近项目列表提供持久入口，不应在用户处理当前项目时抢占流程。
- 小白案例：后台备份失败需要通知，但不应立刻关闭你正在编辑的文档。

### G28. 其他项目需要处理冲突（改为项目状态）

- 用户触发：后台 AI 完成时，源文件也被外部修改。
- 系统条件：AI 候选与外部 HTML 都有效，不能静默覆盖。
- 当前反馈：最近项目列表标记“需要处理”；切回项目后，冲突面板说明两份内容都已保留。
- 用户操作：切回项目比较并选择。
- 为什么不弹全局错误：选择属于对应项目；持续项目状态比跨项目弹窗更稳定。
- 小白案例：云盘发现本地版和云端版同时修改，必须让你选，而不是随机覆盖。

### G29. 本轮文件无法在文件夹中打开（已取消提醒）

- 用户触发：在 AI 处理面板点击“在文件夹中打开 AI任务”。
- 系统条件：自动尝试后仍无法显示。
- 当前结果：调用已删除，不弹出。任务仍在处理面板中。
- 实际反馈：原面板入口仍可再试。
- 设计理由：任务本身不受影响，辅助入口失败不另弹全局提醒。

### G30. 历史版本无法在文件夹中打开

- 用户触发：点击历史版本的“在文件夹中打开”入口。
- 系统条件：自动尝试后仍无法显示版本文件。
- 当前文案：“历史版本暂时无法在文件夹中打开”“请确认项目记录仍然完整后重试。”
- 样式与时长：警告色、`background-result`、8 秒。
- 用户操作：从原历史卡片再次尝试。
- 为什么提醒：不影响当前 HTML，也不需要创建额外重试按钮。
- 小白案例：相册里的老照片还在应用中，只是无法打开所在文件夹。

### G31. 无法打开某个历史版本（已取消提醒）

- 用户触发：点击历史版本卡片。
- 系统条件：自动读取后仍失败。
- 当前结果：调用已删除，不弹出。原来的画布仍保持不变。
- 实际反馈：历史卡片仍在，可再点打开。
- 设计理由：版本没切换本身就是结果。

### G32. 无法返回当前 HTML（已取消提醒）

- 用户触发：从历史浏览点击“返回当前 HTML”。
- 系统条件：当前文件读取失败。
- 当前结果：调用已删除，不弹出。当前画布仍停留在原来的历史版本。
- 实际反馈：返回入口仍在。
- 设计理由：视图没切回当前 HTML，用户已经看到自己仍在历史只读视图。

### G33. 用历史内容替换当前 HTML（能力已取消）

- 原问题：历史卡片既承担只读审阅，又提供回写当前 HTML，产生确认、写入、回读与失败恢复等整套分支。
- 当前行为：历史版本只读查看；可以回到当前 HTML 或在 Finder 中定位历史文件，不提供“设为当前 HTML”。
- 为什么取消：历史审阅的主目标是追溯，不应顺手变成覆盖当前源码的高风险入口。
- 小白案例：档案室允许查看旧合同，但不会在查看按钮旁放一个“覆盖当前合同”。

## 9. Canvas 内编辑提示

以下提示只出现在用户正在编辑的 Canvas 内，不占用全局消息出口。
编辑受阻类提示（C02、C05、C06、C09、C10、C11）已全部移除：编辑
仍 fail-closed 拒绝、页面内容不变，具体原因只写入画布
`data-edit-block-detail` 诊断属性，不再向用户弹出任何气泡。

### C01. 页面暂时不能建立源码映射

- 用户触发：打开 HTML 或重新载入页面。
- 系统条件：源码索引无法建立，不能证明视觉文字与源码位置一一对应。
- 当前文案：标题“暂时不能直接编辑这个页面”；正文“页面仍可正常浏览。请重新载入后再试，或添加评论说明要改什么。”
- 操作按钮：“重新载入”或“重新选择”，取决于是否已经绑定本地源文件。
- 样式与时长：错误色、持续显示。
- 用户操作：重新载入；仍失败时改用评论描述需求。
- 为什么提醒：继续直接编辑可能修改错误源码位置。
- 小白案例：地图定位系统失效时可以继续看地图，但不能假装知道你点击的是哪条街。

### C02. 默认的直接编辑受阻已静默

- 用户触发：双击、输入、删除、粘贴、调整样式或排序。
- 系统条件：底层 Source Patch 无法安全应用，但没有命中更具体的原因。
- 当前文案：不再弹出提示。编辑照旧 fail-closed 拒绝，页面内容不变；具体原因只写入 `data-edit-block-detail` 供诊断。
- 操作按钮：无。不再发出 `canvas_c02_edit_blocked` 用户提示。
- 用户操作：重新选中可编辑文字，或自行添加评论交给 AI。
- 为什么不再提醒：拒绝本身已守住源码安全，短提示在连续输入时反复打断；评论入口常驻右侧，无需每次复述替代路径。
- 小白案例：笔到不了的地方轻轻放下就好，需要改动时再开口（写评论）。

### C03. 样式边界自动放置光标

- 用户触发：在两段样式交界处双击或输入。
- 系统条件：折叠光标落在非空行内样式交界。
- 当前文案：不再阻止进入或输入。系统按亲和性自动放置光标：可视段首继承右侧首字符，其余交界继承左侧字符。
- 操作按钮：无。不再发出 `canvas_c03_style_boundary` 用户提示。
- 用户操作：直接在自动放置的光标处输入。
- 为什么不再提醒：自动选择一侧与工具栏预告的下一次输入样式一致，不必先把光标挪进某个字里。
- 小白案例：红字和蓝字交界处插字时，系统已经决定新字跟哪一侧，不必先问你。

### C04. 空排版元素旁自动放置光标

- 用户触发：在空的排版标签附近双击或输入。
- 系统条件：光标附近存在空的行内排版元素。
- 当前文案：不再阻止进入或输入。系统把光标放到相邻文字的确定位置，空排版标签保持不动。
- 操作按钮：无。不再发出 `canvas_c04_empty_formatting` 用户提示。
- 用户操作：直接输入；空排版结构仍保留。
- 为什么不再提醒：空盒子不再让编辑停下来，光标被放到唯一安全的文字位置。
- 小白案例：两个空盒子旁边的字仍然可以直接改，系统不会把新字塞进空盒子里。

### C05. 复杂网页结构不能直接改字（已静默）

- 用户触发：在脚本、表单根或不安全嵌入根等不能成为文字岛的内容中输入。
- 系统条件：最小 Source Patch 无法在不伤害结构的前提下完成。
- 当前文案：不再弹出提示，与 C02 一样静默拒绝；底层详情保留结构原因供诊断。
- 操作按钮：无。不再发出 `canvas_c05_complex_structure` 用户提示。
- 用户操作：混合块容器可直接进入同一文字岛，非行内后代保持冻结；其余情况用评论说明修改目标。
- 为什么不再提醒：双击裸文字、写评论这些替代路径不依赖提示复述，静默拒绝同样守住了结构。
- 小白案例：普通文本像便签，复杂组件像机械表，不能用同一种方式拆。

### C06. 特殊布局导致光标可能错位（已静默）

- 用户触发：编辑使用 transform、zoom、多栏、flex、grid 或特殊盒模型的文字。
- 系统条件：视觉光标与源码选择映射不够可靠。
- 当前文案：不再弹出提示，与 C02 一样静默拒绝；底层详情保留布局原因供诊断。
- 操作按钮：无。不再发出 `canvas_c06_special_layout` 用户提示。
- 用户操作：仍可选中文字调整安全样式，复杂内容改用评论。
- 为什么不再提醒：视觉位置相同不代表源码位置相同，安全拒绝已足够；提示无法帮用户修好布局。
- 小白案例：镜子里的位置和真实物体位置不同，不能只看镜像下手。

### C07. 多行粘贴

- 用户触发：在直接编辑状态粘贴包含换行的文本。
- 系统条件：当前结构可以精确映射时正常写回；只有实际无法建立安全 Source Patch 时才进入统一编辑受阻提示。
- 当前文案：支持时无提醒；不支持时与 C02 一样静默拒绝，底层详情保留“当前结构暂不支持多行粘贴”供诊断。
- 用户操作：支持时照常编辑；真正受阻时可换一个明确文字位置，或添加评论。
- 为什么不单独提醒：多行本身不是错误，限制应以实际映射能力为准。
- 小白案例：替换一句话和插入三段新章节不是同一种编辑。

### C08. Enter、新增段落或换行

- 用户触发：按 Enter 或执行新增段落。
- 系统条件：当前段落结构可以精确映射时正常创建最小结构 Patch；无法证明位置时才停止。
- 当前文案：支持时无提醒；不支持时与 C02 一样静默拒绝，底层详情保留具体原因。
- 用户操作：支持时照常按 Enter；真正受阻时改用评论描述结构调整。
- 为什么不单独提醒：支持的正常输入不应被“安全策略”打断。
- 小白案例：改一行字可以直接做，拆成两个段落需要重新排版。

### C09. 图片、图标或组件不能这样删除（已静默）

- 用户触发：用 Delete/Backspace 跨越非文字结构。
- 系统条件：删除范围包含图片、图标、嵌入组件或结构边界。
- 当前文案：不再弹出提示，与 C02 一样静默拒绝；底层详情保留删除原因供诊断。
- 操作按钮：无。不再发出 `canvas_c09_structure_delete` 用户提示。
- 用户操作：缩小文字选择，或明确写评论。
- 为什么不再提醒：静默拒绝同样守住了结构边界；需要删除结构时评论是既定路径。
- 小白案例：删掉一句文字和拆掉整张图片不是同一风险等级。

### C10. 输入法没有完整确认（已静默）

- 用户触发：使用中文输入法时输入过程被中断或浏览器未完成 composition。
- 系统条件：无法证明候选文字已经完整提交。
- 当前文案：不再弹出提示，仍恢复输入前文字；底层详情保留输入法原因供诊断。
- 操作按钮：无。不再发出 `canvas_c10_ime_incomplete` 用户提示。
- 用户操作：点回文字重新输入；重复失败时用评论。
- 为什么不再提醒：恢复到输入前状态本身就是可继续编辑的稳定状态；提示无法替用户完成候选确认。
- 小白案例：拼音候选还没选完就切走，应用不应把半成品当最终文字。

### C11. 页面变化导致原文字位置漂移（已静默）

- 用户触发：页面更新后继续编辑旧选择。
- 系统条件：源码节点、目标或唯一文本映射已经变化。
- 当前文案：不再弹出提示，与 C02 一样静默拒绝；底层详情保留映射漂移原因供诊断。
- 操作按钮：无。不再发出 `canvas_c11_target_drift` 用户提示。
- 用户操作：再次点选目标，或添加评论。
- 为什么不再提醒：再次点选是最自然的重试动作，无需提示教一遍。
- 小白案例：地图更新后道路编号变了，重新点一次目的地即可。

### C12. 当前文字输入尚未结束

- 用户触发：输入法或文字编辑尚未完成时点击预览、项目、保存、发送等跨流程操作。
- 系统条件：编辑 checkpoint 不能安全提交。
- 当前文案：标题“当前文字还在处理中”；正文优先显示具体原因，默认“请点回文字完成输入；已输入的内容仍保留在画布中。”
- 操作按钮：无。
- 样式与时长：警告色，5 秒。
- 用户操作：点回当前文字，完成或取消输入，再继续原操作。
- 为什么提醒：用户已经在正确位置，额外“重试”按钮不能改变输入法状态。
- 小白案例：一句话还没打完时切换文档，先把光标放回去收尾即可。

## 10. 原位持久提醒与决策

### I01. 上次打开的 HTML 无法恢复

- 位置：页面顶部持久横幅。
- 用户触发：启动源页。
- 系统条件：上次活动文件已移动、删除、损坏或不可读。
- 当前文案：“上次打开的 HTML 无法恢复”“文件可能已移动、删除或损坏。源页没有打开其他内容来替代它。”
- 操作按钮：“选择其他 HTML”“暂时关闭”。
- 用户操作：选择其他文件，或关闭提示后继续使用欢迎页。
- 为什么原位显示：这是启动上下文，不应以短 Toast 一闪而过。
- 小白案例：书签指向的文件不见了，应用不能随便打开另一份文件冒充。

### I02. 本地项目资料服务不可用

- 位置：Canvas 上方持久横幅。
- 用户触发：正常编辑过程中本地 Bridge 停止。
- 系统条件：项目记录、附件或版本服务不可用。
- 当前文案：“本地项目资料暂时不可用”“当前页面内容仍保留。可先导出当前 HTML，再重新打开源页。”
- 操作按钮：“导出当前 HTML”“重新定位文件”“重新打开”。
- 用户操作：有未保存内容时先导出；或重新定位源文件；恢复前暂停保存。
- 为什么原位显示：问题持续影响当前页面，需要一直保留恢复入口。
- 定位失败：无法确定工作文件、文件暂不可用、项目暂不可用、无法核对工作文件
  也使用同一横幅，不再另弹 Toast。定位来源的横幅在项目水合、重命名/重定位或
  源文件写入成功后自动清除；生命周期与完整性来源不会被保存空闲态冲掉。
- 为什么不再弹原生窗口：Renderer 已能显示完整恢复路径，重复弹窗会打断用户。
- 小白案例：文件柜服务断开，但桌面上的纸还在；先复印一份，再重启文件柜。

### I03. 源 HTML 外部冲突或写入失败

- 位置：Canvas 上方持久横幅。磁盘监视器在 2 秒内发现外部改写时，也使用同一横幅，不再另弹 Toast。
- 用户触发：直接编辑后自动保存、关闭页面，外部程序同时修改源文件，或重开已有项目后磁盘被改写。
- 系统条件：权威写入/回读确认磁盘内容变化、权限问题、写入失败或内容完整性校验失败；单纯内部 Hash/revision 投影不一致不会进入这里。监视器只做提前预警，写前 Hash 仍是最终防线。
- 当前标题：“源文件在磁盘上被其他程序修改了”或“当前修改还没有写入文件”。
- 当前正文：冲突时默认“您的编辑内容仍在，可先预览外部版本再决定。”；写入失败时强调工作台保留了当前编辑内容。不展示本地路径、ID、Hash 或原始技术异常。
- 操作按钮：冲突时为“导出当前 HTML”“预览外部版本”“采用磁盘版本”；确认写入失败时第二个按钮为“重试更新文件”。
- 用户操作：外部冲突时可先导出或预览，再决定是否采用磁盘版本；普通写入失败则解决文件条件后重试更新。
- 为什么原位显示：这是当前 HTML 的长期安全状态，不应被关闭后失去入口。
- 写入失败与磁盘冲突不再另弹 Toast；`persistState` 横幅就是唯一入口。
- 小白案例：Word 检测到文件被别人改过，需要一直保留另存和重新载入入口。

### I04. 当前项目暂不可编辑

- 位置：右侧评论栏顶部状态卡。
- 用户触发：打开项目。
- 系统条件：项目状态、版本或评论记录读取失败。

- 操作按钮：“重试读取”。
- 用户操作：确认文件仍存在后重试。
- 为什么原位显示：项目读取问题直接影响评论栏和编辑权限，入口就在当前项目。
- 小白案例：档案夹目录没读出来，先在档案夹区域重读，不需要全屏弹窗。
- 已知兼容例外：历史 Version 或已归档终态的 2026 年 8 月 Developer Preview assessment
  可省略或带有现已退役的可执行表面字段。系统先用冻结 base、不可变候选证据与四个 Hash
  重算当前文档健康和连续性结果，在内存中移除旧字段及脚本结论。成功时不进入本状态，
  当前 HTML 继续可编辑；归档结果不被复活。证据无法匹配时仍进入本状态。

### I05. 评论还没有安全记录

- 位置：工作区顶部持久横幅。源 HTML 冲突或写入失败存在时，由 I03 优先占用该表面；源问题解除后，未解决的评论问题再显示。

- 小白案例：比较完成后正式采用 AI 稿；原稿和本轮过程仍可追溯。

- 用户操作：查看原因、调整后重试或取消本轮。

### I19. 应用更新已下载

- 位置：左侧栏 HTML 图标下缘的小号红色斜体 `New! 重启更新`，以及设置页“软件更新”主按钮。
- 系统条件：用户点击 `New!` 或设置页中的“下载更新”后，正式签名的 macOS App 已下载 stable 新版本。
- 当前文案：侧栏“Stemmio <版本> 已下载，重启更新”；设置卡“Stemmio <版本> 已准备好”“点击重启后会先写入当前编辑，然后安装新版本。”

- 克制边界：Canvas 不出现更新 NoticeBar，顶部不新增图标，下载不显示百分比、进度条或动画，也不再询问是否现在重启。
- 小白案例：更新包已经取到本机，点重启就会先收好当前工作再换新版本。

### I20. 设置中的更新检查

- 位置：设置标签页的“软件更新”区块。
- 用户触发：打开设置，点击“立即检查”“下载更新”或常驻的“查看更新内容”。打开 About 不触发更新检查。
- 系统条件：显示当前 stable 更新快照；手动检查时在同一位置进入等待状态，完成后更新为“已是最新”“可以下载”“正在下载”“可以安装”或可读失败原因。
- 当前文案：“正在检查更新”“当前已是最新版本”“Stemmio <版本> 可以下载”“正在下载 Stemmio <版本>”“Stemmio <版本> 已准备好”；不可用时说明“暂时无法连接更新服务”“本机更新服务暂时不可用”“当前构建不检查应用更新”或“浏览器预览不检查应用更新”。
- 操作按钮：主按钮按状态为“立即检查”“下载更新”“重启更新”“正在检查…”“正在下载…”“正在重启…”或“仅正式版可用”；卡内常驻文字链接“查看更新内容”，卡外另有固定“Stemmio Releases on GitHub”项目入口。
- 用户操作：可以主动检查、明确开始下载、在下载完成后直接重启安装，或随时阅读该版本的更新内容。“查看更新内容”在浏览器里打开固定的公开 Release 页，说明正文是该版本经审核的用户更新说明；无更新时读到的就是自己当前版本改了什么。
- 为什么原位显示：用户主动发起的查询需要持续、可复查的确定结果；不再额外发送一条短 Toast。自动检查失败仍保持静默，不打断编辑。更新内容页面没有打开时，失败说明也留在同一张卡下方。
- 安全结果：手动检查与启动后、每 4 小时的自动检查复用同一主进程控制器；渲染器不能传入任意更新频道、下载地址或外部链接，“查看更新内容”也只能请求主进程持有的固定 Release 地址。
- 小白案例：像在应用设置里查看版本、按一次“检查更新”，并能顺手点开“这次更新改了什么”，结果一直留在刚才操作的位置。

## 11. 持续状态：不是提醒，但用户会看到

### S01. 文件写入与恢复事实

- 位置：标签页状态点、Canvas/评论恢复提示和关闭安全核对；正常写入不占用顶栏。关闭被拦住时顶栏持续“正在保存，完成后将退出”；已保存刷新成功时顶栏短暂“已加载磁盘最新版本”。
- 可见事实：只有冲突、失败或需要用户处理时进入全局恢复提示；正常写入不显示绿色成功点或状态文字。
- 只读模式：浏览器预览和历史查看继续在各自页面表达只读语义，不占用顶栏保存状态。
- 为什么这样显示：保存、冲突和失败仍由 Document/Project 工作流持有，用户不需要读取一个会反复变化的顶栏状态。
- 小白案例：文件出问题时保留明确的恢复入口，文件正常写回时让页面保持安静。

### S02. Canvas 锁定或历史只读状态

- 位置：Canvas 内状态标记和顶部历史横幅。
- 状态文案：“本轮已锁定，仅可滚动浏览”“正在查看历史版本，只读”“正在预览已发送 HTML”“浏览器预览 · 只读”。
- 用户操作：按当前流程返回编辑或等待处理。
- 为什么不是警告：这是可预期模式，不是异常。
- 小白案例：查看 PDF 时显示“只读”，不需要弹错误。

### S03. Agent 交付状态

- 位置：顶部发送按钮和本轮流程。
- 状态文案：
  - “写评论后再发送”
  - “发给 AI”
  - “正在准备…”
  - “正在复制…”
  - “正在启动 Qoder CLI”
  - “Qoder 正在读取本轮任务”
  - “Qoder 正在写入候选 HTML”
  - “Qoder 正在完成最终化”
  - “查看本轮”
  - “复制失败，再试一次”
- 用户操作：发送前在同一弹窗选择“Qoder CLI”或“复制任务”。使用前检查的未安装、
  需要登录、版本/包身份不受支持和暂时无法检查都在 Qoder 卡内原地显示，不用全局
  Toast。自动模式普通失败且
  已确认无进程/输出残留时，可从本轮面板“重新启动 Qoder”或“复制任务”；Bridge 崩溃、
  清理未知或存在残留时只能结束旧 Request 后重新发送。复制失败时从底部“重新复制”。
  设置卡与侧栏接入结果也原位显示：登录停止未确认、已连接但 API Key 未保存、
  退出/断开按全应用任务影响确认、以及“当前文件已变化，不会重新发送”。
- 为什么不是全局 Toast：按钮和流程板已经是权威状态来源。
- 小白案例：上传进度显示在上传按钮上，比另弹一个进度框更清楚。

### S04. AI 本轮四阶段流程

- 位置：本轮处理面板。
- 固定阶段：
  1. 启动 Qoder CLI，或准备并复制。
  2. 等待 AI 完成。
  3. 校验并保存。
  4. 结果。
- 内部身份、Hash、完整性、范围和事务检查全部归入第三阶段，不再逐条暴露。
- ACP stop/progress 不能替代 completion；completion 出现前第二阶段不能显示完成。Agent 启动失败、复制失败、校验失败和外部冲突分别落在真实发生的阶段。
- 成功、无变化和冲突选择使用底部操作；流程卡片本身不再重复放置按钮。
- 为什么不是 Toast：这是一段长流程，用户需要回看完整上下文。
- 小白案例：快递页展示“已寄出、运输中、派送中、已送达”，不会把每一次内部扫描都列成用户步骤。

## 12. Renderer 确认弹窗

### B01. 离开浏览器预览（确认已取消）

- 当前行为：纯浏览器预览是正式只读能力，不能修改 Stemmio HTML，也没有待保存的编辑，因此离开时不询问。
- 页面自身交互：表单、脚本或临时页面状态可以运行，但顶部持续说明“操作不会保存”。
- 小白案例：在产品演示页里展开菜单不会改动产品源文件，离开时无需弹“是否保存”。

### B02. 重新载入会舍弃未写回修改

- 用户触发：存在本地未写回内容时点击重新载入。
- 当前文案：“重新载入会舍弃尚未写回的当前编辑内容。建议先导出 HTML 副本，仍要继续吗？”
- 用户操作：取消后导出，或确认舍弃并载入磁盘版本。
- 为什么必须确认：这是明确的内容丢弃选择。
- 小白案例：刷新表单会清空未提交内容，需要先问一次。
- 冲突路径：源文件已被其他程序修改时，重新载入会覆盖当前编辑，改用“确定要用外部版本覆盖当前编辑吗？此操作不可撤销。”；冲突横幅“采用磁盘版本”仍用“确定要用磁盘上的版本继续吗？…”。已保存且无未写回编辑时直接刷新，顶栏短暂显示“已加载磁盘最新版本”。

### B03. 用历史版本替换当前 HTML（入口已取消）

- 当前行为：历史版本仅供只读查看，界面和 Bridge 都不提供恢复/替换操作，因此没有确认弹窗。
- 用户操作：可回到当前 HTML，或在 Finder 中查看历史文件。
- 小白案例：旧版档案可以翻阅，但不会从阅读页直接覆盖现行文件。

### B04. 结束已复制给外部 Agent 的本轮

- 用户触发：剪贴板交接已成功后，点击“结束本轮并继续编辑”。
- 当前文案：
  - 标题“AI Agent 可能仍在修改”
  - 说明“结束本轮后，AI Agent 的修改将不会保存到源页。建议先停止 AI Agent。”
- 操作按钮：“结束本轮并继续编辑”“继续等待”；“继续等待”默认获得键盘焦点。
- 安全结果：`Escape`、点击遮罩或“继续等待”只关闭弹窗；确认结束才写入取消终态并恢复编辑。
- 为什么必须确认：源页只能结束自己的 Request，不能自动停止外部 AI Agent。用户需要在放弃接收本轮结果前知道这一点。
- 小白案例：像停止等待外部上传结果；本地页面可以恢复操作，但远端任务需要单独停止。

受管 Qoder ACP 不使用这张弹窗。其原位操作为“停止 Qoder 并继续编辑”；源页先停止它
拥有的 Qoder 会话与进程组，再持久取消本轮并恢复编辑。停止完成前按钮显示“正在停止
Qoder…”，Canvas 继续锁定。

### B05. 首次导入外部 HTML

- 用户触发：打开一份尚未关联 Stemmio 项目的本地 `.html` / `.htm`。
- 当前行为：直接导入并打开，不再弹出确认框。
- 仅当本次意图包含删除原稿时，才出现已登记确认：“成功导入后会将原文件移至废纸篓。确定继续吗？”
- 安全结果：取消删除确认则中止导入；普通导入零确认创建项目。
- 为什么不再确认普通导入：复制进项目目录不是覆盖或删除用户原件。
- 小白案例：把下载的网页放进资料库时直接开始工作，只有要扔掉原件才再问一次。

### B06. 再次打开已导入原稿

- 用户触发：打开一份已经关联项目的外部原文件。
- 当前行为：直接打开该项目当前可编辑工作稿，不再弹出确认框。打开的不是原稿，也不是只读最新版本。
- 安全结果：工作稿内容不变；不会再次复制一份。
- 为什么不再确认：再次打开不会覆盖或删除用户内容。
- 小白案例：再次点开当初下载的原稿，是回到正在编辑的那份工作稿。

## 13. macOS 原生提示

### M01. 导出位置会覆盖当前源文件

- 用户触发：导出 HTML 副本时选择了当前源 HTML、等价路径或硬链接。
- 当前行为：自动改用下一个空闲的 `-副本` / `-副本-N` 文件名，不再弹出系统消息框。系统保存框自身的覆盖确认仍由操作系统处理。
- 为什么不再使用原生提示：另存不会覆盖原件，改名即可继续。
- 小白案例：另存副本不能把原件覆盖掉，所以直接帮你换成不冲突的名字。

### M02. 暂时无法安全关闭

- 用户触发：关闭窗口或退出应用。
- 系统条件：仍有更改尚未安全写入，且关闭结果要求重试。
- 当前行为：不弹原生框；暂时阻止关闭，顶栏持续显示“正在保存，完成后将退出”，主进程在后台重试关闭核对。身份无效或脏加载失败等硬失败不重试，回到当前页面。
- 为什么不再使用原生提示：Renderer 已能承担持续状态，重复系统警报只会打断编辑。
- 小白案例：关门时还在把文件放进抽屉，门口显示“正在收好，随后离开”，而不是再按一次门铃。

### M03. 关闭协调本身异常

- 用户触发：退出应用。
- 系统条件：关闭协调代码抛出未预期错误。
- 当前行为：取消关闭并写日志；不再弹出系统错误框。内部详情只留在日志。
- 为什么不再使用原生提示：用户已经停在当前页面，可以继续处理。
- 小白案例：门锁控制器自己故障时，门保持开着，并记下原因。

### M04. 重新打开前仍有未写入内容

- 用户触发：点击“重新打开源页”。
- 系统条件：重新打开前的关闭确认尚未完成。
- 当前行为：与 M02 相同，走应用内顶栏与重试，不弹原生框。
- 小白案例：重启前发现文档未保存，先留在文档里写完。

### M05. 重新打开协调本身异常

- 用户触发：重新打开应用。
- 系统条件：重启协调失败。
- 当前行为：取消重新打开并写日志；标题仅用于日志“暂时无法重新打开源页”。
- 小白案例：系统重启命令本身失败，人还留在当前桌面。

### M06. 本地项目服务停止，且 Renderer 尚不可用

- 用户触发：启动或早期恢复过程中 Bridge 停止。
- 系统条件：页面还没有加载到能显示应用内横幅的阶段。
- 当前行为：把恢复信息留在邮箱里，等 Renderer 可显示时改为 I02 危急横幅；不再弹出系统消息框。
- 去重规则：Renderer 一旦加载，只保留 I02。
- 小白案例：店内广播系统没启动，门口告示等店门打开后再贴在店里。

### M07. 源页启动失败

- 用户触发：启动应用。
- 系统条件：主窗口或关键启动流程抛出错误。
- 当前文案：标题“源页启动失败”；详情为启动错误。
- 后续：显示错误后退出。
- 为什么使用原生提示：正式界面根本没有建立。
- 小白案例：应用连首页都打不开，只能由系统错误框说明。

## 14. 代码中存在、但当前不会弹出的消息

这些条目曾经进入 `setToast`，但当前不会作为全局 Notice 出现。它们仍值得记录，因为测试和未来改动需要知道“为什么没出现”。

### N01. 更新页面没有打开

- 定义文案：“更新页面没有打开”“当前内容不受影响；可以重新打开 Stemmio 发布页。”
- 当前结果：不弹出。
- 用户仍可操作：左侧栏 `New!` 入口仍在，可再次点击。
- 设计理由：更新页面是辅助入口，不应盖过当前编辑。

### N02. 已恢复上次未写回的编辑（已取消提醒）

- 定义文案：“已恢复上次未写回的编辑”“工作台正在把异常退出前的内容安全更新到源 HTML。”
- 当前结果：调用已删除，不弹出。
- 实际反馈：正常恢复不打断用户；只有无法安全写回时进入工作区危急状态。
- 设计理由：恢复成功不需要打断用户。

### N03. 评论附件副本清理失败

- 定义文案：“附件已从评论移除”“项目中的附件副本暂时无法清理。”
- 当前结果：不弹出。
- 实际结果：附件已从当前评论移除；残留清理由项目记录负责。
- 设计理由：用户主任务已经完成，不为后台清理制造阻断。

### N04. HTML 副本导出成功（已取消提醒）

- 定义文案：“已导出 HTML 副本”；桌面路径还会显示保存文件名。
- 当前结果：调用已删除，不弹出。
- 实际反馈：导出对话框与目标文件已经提供结果。
- 设计理由：成功动作不需要额外遮挡 Canvas。

### N05. 外部文件重新载入成功

- 定义文案：曾为 Toast“已重新载入外部文件”“工作台现在显示磁盘上的最新内容。”
- 当前结果：不弹出 Toast。
- 实际反馈：顶栏短暂显示“已加载磁盘最新版本”；Canvas 内容和冲突横幅直接变化。
- 设计理由：页面变化本身就是更强的成功证据，短暂状态条只确认已读到磁盘版本。

### N06. 复制模式交接内容失败（已取消提醒）

- 定义文案：“交接内容还没有复制”“这次任务还在，打开本轮后可以重新复制”
- 当前结果：调用已删除，不弹出。
- 实际反馈：复制失败时顶部按钮变为“复制失败，再试一次”；流程显示“交接内容尚未复制”，底部提供“重新复制”和“取消本轮”。
- 设计理由：同一问题已有三个原位信号，不再重复全局提示。重新复制本身仍保留 N5 Toast，因为剪贴板没有其他可感知结果。

### N07. 当前项目打开了有协议警告的候选版本

- 定义文案：“版本 N 已打开，但需要检查”；说明临时输出在最终化后发生变化，但已提交版本未受影响。
- 当前结果：不弹出。
- 实际反馈：警告保留在本轮处理记录。
- 设计理由：版本已安全打开，详情适合回到审计面板查看。

### N08. AI 候选已取消

- 用户触发：复制模式在 B04 中确认“结束本轮并继续编辑”。
- 当前结果：显示 `background-result` NoticeBar，通常 8 秒后自动消失。
- 当前文案：“本轮已结束，已恢复编辑”“AI Agent 不会被自动停止；如仍在运行，请手动停止。”若用户已切换到其他项目，标题缩短为“本轮已结束”。
- 操作按钮：无；保留统一“关闭提醒”。
- 实际反馈：处理面板收口、当前源 HTML 恢复编辑；迟到 finalizer 得到不可重试的取消终态，不生成新版本。
- 设计理由：恢复编辑本身可见，但外部 AI Agent 不会被源页停止；面板关闭后需要保留一次简短、直接的手动停止提醒。
- 受管 Qoder 模式不进入 N08：Bridge 已先停止它拥有的 Qoder 会话，恢复编辑本身即为完成反馈，不显示“请手动停止”这一错误提示。

### N09. 已选择保留外部 HTML

- 定义文案：“已保留外部 HTML”“AI 候选没有覆盖源文件……”
- 当前结果：不弹出。
- 实际反馈：冲突面板关闭，Canvas 读取外部内容。
- 设计理由：用户刚作出的选择不需要再次通知确认。

### N10. 历史内容已设为当前 HTML（定义已删除）

- 当前结果：界面和 Bridge 都没有历史回写入口，也不再保留对应成功消息。
- 设计理由：历史版本是只读审阅能力，不应产生覆盖当前源码的旁路。

### N11. 延迟后会自动继续的项目切换状态

- 定义文案包括：
  - “正在准备本轮任务”“当前操作结束后会自动打开目标项目。”
  - “正在核对当前画布”“核对完成后会自动打开目标项目。”
  - “检测到新的画布修改”“新修改保存后，会自动打开目标项目。”
- 当前结果：不弹出。
- 实际反馈：目标项目意图被系统记录，条件解除后自动继续。
- 设计理由：没有用户动作，弹出只会让用户误以为需要处理。

## 15. 为什么有些地方仍保留“重试”

“不显示重复重试 Toast”不等于产品中不能有任何重试。当前允许的重试必须满足至少一个条件：

1. 它位于失败对象的唯一恢复表面，例如工作区顶部“重试记录评论”、文件页“重试读取”。
2. 第一次动作没有产生不可重复的写入，例如读取最近项目。
3. 系统已经明确确认原操作没有成功，例如 Request 明确未建立。
4. 重试会改变条件或走新的安全路径，例如“重新选择位置”。

以下重试被禁止：

- Request 结果未知时再次提交。
- 写入结果未知时再次写入。
- 取消结果未知时再次取消。
- 原入口仍清晰可见时，再在 Toast 中复制一个同义按钮。

## 16. 文案结构规则

每条异常文案按以下顺序写：

1. 标题：发生了什么。
2. 正文第一句：哪些内容已经安全保留或没有被修改。
3. 正文第二句：如果用户必须行动，明确说下一步。
4. 按钮：写清对象和结果，不使用脱离上下文的“处理”“查看”“重试”。

推荐：

- “副本没有导出。当前源 HTML 没有被改动。请选择其他位置。”
- “页面变化较大。候选 HTML 已保留，请先审阅对比。”
- “评论和附件仍保留；重新选择画布位置即可继续。”

不推荐：

- “操作失败。”
- “请重试。”
- “处理第一条。”
- “无视本校验，继续。”
- “未知错误：runtime-state revision hash mismatch。”

技术错误在展示前会移除 Electron IPC 前缀、异常类名、堆栈，并把 `runtime-state`、`revision`、`hash` 转成“项目运行状态”“编辑状态”“内容校验”。可见错误最长约 280 字。

## 17. 维护与测试要求

新增或修改提醒时，必须同时回答：

1. 系统能否自动恢复？
2. 这条信息是否已经能在原控件显示？
3. 用户是否必须改变条件或作决定？
4. 按钮是否改变失败条件，而不是原样重复动作？
5. 消息关闭后，真实问题是否仍有原位状态？
6. 是否明确说明原文件、评论、附件或候选版本是否安全？
7. 是否使用普通用户语言？
8. 是否有聚焦、键盘和屏幕阅读器语义？
